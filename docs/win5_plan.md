## 0. WIN5 の仕様（前提の確認）

- 2011年〜。JRA 指定の **5レースの1着**を全部当てる。1口 **100円**。
- **払戻率 70%（控除率 30%）** ← 単勝/複勝の約20%より重い。ここが最大の逆風。
- **1口あたり払戻に上限**あり（要確認: 現行の上限額 ≒ 6億円/口 規模）。上限超過分は繰越。
- **キャリーオーバー発生**: (a) 的中票0、または (b) 払戻が上限超過 → 次回 WIN5 のプールに繰越。
- 対象5レースは事前公表。各レースの我々の勝率ベクトルは v6 / T-10 blend から出せる（[[project_t10_hosei_marks]]）。

## 1. EV 式（この計画の心臓）

1口 100円で組み合わせ c=(h₁..h₅) を買うときの期待値。レースは独立なので：

```
EV(c) / 100  =  E_edge(c) × (0.70 + CO/売上)  −  1

  E_edge(c) = Π_i [ p_i(h_i) / q_i(h_i) ]      ← 我々の勝率 / 市場(crowd)勝率 の積（レッグごと）
  0.70      = 払戻率（控除30%の裏返し）
  CO/売上   = 今回の繰越金 ÷ 今回の売上（プール補助の強さ）
```

導出の要点: 的中時払戻 ≈ プール ÷ 的中票数。的中票数 ≈ (売上/100) × Π q_i(勝ち馬)（群衆は市場勝率に比例して各レッグを選ぶと近似）。プール = 売上×0.70 + CO。これを整理すると按分の分母(市場)と的中確率(我々)が上式に factorize する。

### ここから即座に出る2つの結論

**① 繰越ゲート（いつ買うか）** — 我々の予測エッジは≈0（E_edge≈1）。すると +EV 条件は：
```
0.70 + CO/売上 ≥ 1     ⟺     CO/売上 ≥ 0.30
```
→ **繰越が「今回の売上の30%以上」あって初めて期待値中立。それ未満は買うだけ −EV の寄付。**
※罠: 大きな繰越がある回は群衆が殺到して売上も膨らむ → CO/売上 は縮む。「繰越◯億」の絶対額でなく **売上に対する比**で判定する。ここが素人と分かれる肝。

**② エッジがあれば閾値が下がる** — もし contrarian 選択で E_edge=1.1 を作れれば、必要 CO/売上 は 1/1.1−0.70 = **0.21** に低下。だが我々の p≈q なので当面 E_edge≈1 前提で設計する（希望的観測をしない）。

## 2. 点数・formation の決め方（ユーザーの直球質問への答え）

### コスト構造（多点は掛け算で爆発する）
各レースで nᵢ 頭選ぶと **点数 = n₁×n₂×n₃×n₄×n₅、金額 = 100円 × 点数**。

| formation 例 | 点数 | 金額 |
|---|---|---|
| 1・1・1・1・1（全部本命1点） | 1 | 100円 |
| 1・1・2・3・3 | 18 | 1,800円 |
| 1・2・3・3・3 | 54 | 5,400円 |
| 2・2・3・3・3 | 108 | 10,800円 |
| 3・3・3・3・3 | 243 | 24,300円 |
| 1・1・5・5・5 | 125 | 12,500円 |
| 4・4・4・4・4 | 1,024 | 102,400円 |

→ **1レース頭数を増やすたびコストが掛け算**。全部3頭で早くも¥24,300。予算は一瞬で溶ける。だから配分が全て。

### 配分ロジック（EV式から一意に落ちる）
EV(c)=100×[E_edge(c)×K − 1]（K=0.70+CO/売上 は回ごとの定数）。組合せ c が +EV ⟺ **E_edge(c) ≥ 1/K**。E_edge(c)=Π(pᵢ/qᵢ)。よって：

1. **各馬を「価値比 pᵢ/qᵢ（我々の勝率÷市場勝率）」で採点**。>1＝我々が市場より高く買う＝妙味。
2. **価値比の高い馬から各レースに入れる**。確信本命（pᵢ/qᵢが飛び抜け＆勝率高）は **1点（軸）**でレッグを締め、点数の掛け算を抑える。
3. **荒れ・混戦レース**（誰も抜けてない＝pᵢ/qᵢが横一線）は **3〜5頭に広げる**。掛け算コストを払う価値がここに集中。
4. **上限配当に張り付く超ロングショット偏重の目は避ける**（払戻が cap で切られて EV が削れる）。
5. **予算内で点数は多いほど良い**（同じ per-combo EV なら的中確率↑＝分散↓）。ただし ①エッジ≈0 なので「当てにいく多点」は −EV 回では無意味。**多点で殴るのは +EV（繰越）回だけ**。

> 要するに点数は「本命堅い所は1点で締め、割れてる所だけ広げ、価値比の高い馬を優先、予算の許す範囲で点数を盛る」。そして **その多点を切るのは繰越ゲートを通った回に限る**。

## 3. 資金管理（破産しない）

- 的中確率は極小（本命寄せでも1回あたり ~0.1〜1%）。**+EV 回でも分散は天文学的**。
- +EV 回は年に数回しか来ない → エッジの実現に何年もかかる → **「収入」でなく「わずかに順張りの宝くじ」**と割り切る。
- サイズ: fractional Kelly を大幅ディスカウント（推定 CO/売上 も的中票数モデルも誤差大）。目安 **1回 = バンクロールの1〜2%上限**、K が大きい（繰越厚い）回ほど厚く。
- 既存の枠方針（[[project_bet_tier_policy]]）とは別枠管理。週次¥100k floor に食い込ませない。

## 4. データ取得（★これが唯一のブロッカー）

バックテストで「繰越ゲートが本当に +EV か」を CI 付きで検証しない限り、実戦投入しない。必要データ（TARGET か JRA 公式、WIN5 は2011〜）：

| 項目 | 用途 |
|---|---|
| 各回の日付・対象5レースID | レース紐付け |
| 5レースの1着馬番 | 的中判定 |
| 売上金額（発売票数） | プール・按分分母 |
| 払戻金（1口あたり）・的中票数 | 実測按分の検証 |
| **キャリーオーバー額（繰越金）** | ゲートの核 |

→ ユーザーに TARGET エクスポート依頼（無ければ JRA 公式の WIN5 結果ページに払戻・売上・繰越が出る＝スクレイプ可、要許可）。

## 6. 正直な事前見通し

- 控除30%は重く、CO/売上≥0.30 を満たす回は稀（群衆殺到で希釈）。**「たまに来る、わずかに+EVの宝くじ」が現実的な上限**。
- 予測エッジ≈0 なので WIN5 の edge は純粋に構造（繰越）＋按分ゲーム。**精度改善は WIN5 にも効かない**（この点は覚悟の上で入る）。
- Phase 1 で「繰越回も上限cap＋按分で −EV」と出る可能性は十分ある。その時は WIN5 も dead 認定して畳む（憶測でなくデータで殺す＝本プロジェクトの流儀）。
