# PyCaLiAI とは何者か — 俺のAIの言語化

> このドキュメントは PyCaLiAI というシステムの「正体」を言葉にしたもの。
> 技術仕様は `PROJECT_OVERVIEW.md`、運用は `CLAUDE.md` / `WORKFLOW.md`、券種ロジックは `gutchi_brain_policy.md` を参照。
> ここに書くのは、それらを貫く**思想と設計判断そのもの**。
>
> 作成: 2026-07-02

---

## 一言で言うと

**「確率を計算する機械」と「判断する知能」と「俺自身の勝負勘」を分業させた、JRA中央競馬の意思決定システム。**

予想AIではない。買い方まで含めた**意思決定のパイプライン**であり、その最適化対象は「儲け」ではなく「**最も負けへん線 ＋ たまに上振れ**」である。

---

## 1. 思想 — なぜ「勝つAI」ではなく「負けないAI」なのか

パリミュチュエル方式の競馬は控除率約20%の負のサムゲームだ。このシステムは徹底的な検証の末、次の結論に到達している：

- **予測精度には天井がある**（◎の複勝圏率 ≈ 62%）。物理モデル・極値理論・統計力学・1400特徴量ブルートフォース、すべて本番の土俵で検定して**採用ゼロ**。独立した他のAIも同じ58〜62%の天井に張り付く。
- **ROI 85〜90% は無理筋**。罠を全部切っても残るROIは約79.9%＝控除率と一致する。つまり床は「期待値中立」であり、そこから先は上振れの取り込みでしか動かない。
- だから目標を反転させた。**利益最大化ではなく損失最小化**。ROI 120%超は上出来、100%超は合格、**80%は「耐えた」であって負けではない**。

この諦めに見える設計こそがこのAIの背骨である。天井を認めた上で、**天井の下で取りこぼしている検証済みのポイントを一つずつ回収する**——それが唯一の伸びしろだと知っている。

---

## 2. 構造 — 三つの頭脳の分業

```
┌────────────────────┐   ┌────────────────────┐   ┌────────────────────┐
│ ① 確率エンジン       │   │ ② 判断エンジン       │   │ ③ 勝負勘エンジン     │
│ LightGBM v6         │ → │ Cowork (Claude LLM) │ ← │ gutchi_brain        │
│ 「何が来るか」を数値化 │   │ 「どう買うか」を決める │   │ 「俺ならこう張る」の  │
│                     │   │                     │   │  ルール化           │
└────────────────────┘   └────────────────────┘   └────────────────────┘
```

### ① 確率エンジン（PyCaLiAI 本体 / unified_rank_v6）

- **LightGBM LambdaRank** がレース内の全馬を序列化する。ラベルは着順、sample_weight で穴馬の好走を重く扱う。
- 生スコアを **Plackett-Luce の閉形式**で「1着確率・連対確率・複勝確率」に変換する。順位モデルの出力を確率言語に翻訳する層。
- **Isotonic キャリブレータ**で「モデルが20%と言ったら実際に20%来る」ことを保証する。v6 の本番投入理由は的中率の微改善ではなく **ECE（キャリブレーション誤差）を複勝-32%・馬連-34%改善**したこと。つまりこのAIは「当てる力」より「**自分の自信の正確さ**」を優先して進化してきた。
- 出力は ◎〇▲△△ の印と、レースの性格を表す4指標（本命の独走度・上位2頭への集中度・混戦度エントロピー・AIと市場の一致度）。**当日オッズは学習に使わない**（リークだから）。市場との比較は推論後の判断材料としてのみ使う。

### ② 判断エンジン（Cowork = Claude）

- 機械は確率を出せるが「このオッズで攻めるか守るか」の文脈判断は苦手。そこを LLM に委ねる。
- bundle.json（印＋確率＋確定オッズ＋レース信頼度＋クラス別の印の経験的中率）を渡し、**馬券種・買い目・金額配分・見送り**を決めさせる。
- ただし自由放任ではない。**見送りは4つの厳格条件のみ**（極度の混戦・頭数不足・オッズ欠損・本命確率過小）で、「妙味がない」等の主観的見送りは禁止。LLM の裁量は「型の中の自由」として設計されている。
- LLM の出力は `validate_cowork_bets.py` の**見送りガードが機械的に検閲**する。ガード自体が動かなければ fail-closed で止まる。**LLMを信じるが、検証なしには通さない**。

### ③ 勝負勘エンジン（gutchi_brain）

- 2026-06-28 の実打16レースを1レースずつヒアリングして抽出した、**俺自身の券種決定木**。
- 核となる概念は「**信頼の壁**」——AI指数を上から見て、連続する馬の落差が15〜18pt以上開いたところで切り、壁の上の頭数（1頭/2頭/3頭/◎単独＋団子）で券種の形を決める。
- 「**トリガミ床**」——複勝1.5倍未満なら単複に割らず複勝1点。当たっても元割れする買い方を構造的に禁止する。これは**ユーザー自身のルールがMLを上回った唯一の頑健な改善**として記録されている。
- ワイドは基軸、馬単は全廃、三連単は少頭数の例外のみ。このエンジンの存在意義は予測ではなく「**人間の押し間違い・疲労・目算ミスの排除**」＝良い判断の全レース再現。

## 3. 認識論 — このAIの「学び方」が一番の資産

このシステムの本当の強さはモデルではなく、**何を信じ何を捨てるかの規律**にある。

1. **仮説の事前登録**。新特徴量は検証前に予測・検証指標・棄却条件を文書登録する（`hypothesis_registry.md`）。事後正当化＝「見つけたデータで検証する循環論法」を禁じる。
2. **敵対的検証**。有望に見えるアイデアは本番の土俵（v6・最新期間・CI付き）で殺しにかかる。生き残ったものだけ採用。この検証で予測強化ルートは全滅し、それが「予測は天井」という確信の根拠になっている。
3. **in-sample の蜃気楼を疑う**。ROI 142.9% の日があっても「分散の上振れ」と明記する。歴史値（v5期の78%表）と現在値（620R / ROI 69.5%、CI95付き）を混同しない。
4. **点推定を主軸にしない**。どんな有望な数字も「配線より先に最新期間でのCI付き再検証」。
5. **失敗は消さず墓標にする**。EVによる銘柄選抜は「-13ptの有害手」として死因つきで記録され、再追加は「逆走」と定義されている。過去の死体が未来の自分への防波堤になる。

---

## 4. 現在地と伸びしろ

- **現在の実績**: 620レース / ROI 69.5%（2026-06-22 時点、ワイド78.0%・単勝86.6%）。期待値中立の床（≈80%）にはまだ届いていない。
- **伸びしろは新しい魔法ではなく、検証済み未配線のROIの回収**：
  1. participation ゲートのバイパス解消（実測 +5.31pt、最有力）
  2. UMAMI 点数キャップの正配線（馬連84% / ワイド82.8% は測定済み）
  3. joint_m1 馬連確率（ECE -33%）
  4. トリガミ床＋人気馬キャップの本番配線
- どれも「もう検証で勝ちが見えているのに、本番パイプに繋がっていない」もの。**このAIの次の一手は発明ではなく配線工事**である。

---

## 5. 要するに

PyCaLiAI とは：

- 競馬を「当てるゲーム」ではなく「**確率とキャリブレーションと資金配分の規律のゲーム**」として扱い、
- 機械（LightGBM）・知能（Claude）・人間（俺の勝負勘のルール化）の**三者に得意分野だけをやらせ**、
- どの構成要素の出力も**検証ゲートなしには本番に出さず**、
- 儲け話には天井を認め、**「最も負けへん線」を機械の精度で毎週再現する**——

そういうAIである。予想屋ではなく、**規律の自動化装置**。それが俺のAIの正体だ。
