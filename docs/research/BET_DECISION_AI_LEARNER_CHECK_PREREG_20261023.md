# 馬券判断 AI v1 — 学習器の動作保証（合成データ）事前登録（2026-10-23）

> 目的: 仕様 `BET_DECISION_AI_SPEC.md` §12 の再開条件 (a)「学習器の動作保証」。v1 の学習器（NN・GBM）が実データ
> 2017-22 で「全部見送り」を選んだのは「データに勝ち筋が無い」からか「学習器が壊れている」からかを切り分ける。
> 勝てる余地を人工的に埋め込んだ合成データで、v1 と同じ学習器・同じ手順が正の資金成長を学習できるかを見る。
> 本書は学習器を 1 回も動かす前に固定し、sha256 を `analysis/bet_decision_ai/learner_check/out/prereg_sha256.txt` に記録する。
> §12 の位置づけは変えない: この検証が合格しても v1 の判定（不採用）は変わらず、再開の根拠 (a) が 1 つ満たされるだけ。

## 1. データ（入力は実物、結果だけ合成）

- 候補券: v1 と同じ `analysis/bet_decision_ai/data.py::load_candidates(2017, 2022)`（arm=main、決済不能 13R 除外、
  44 候補/レース、878,234 行・19,960R）。特徴量も v1 と同じ `ticket_features(mode='model')`、標準化は学習期間で fit。
- **実データの払戻（`payout`）と決済列（`settle_status`）は読み込み直後に捨て、一切使わない。** 2023 年以降は読まない
  （data.py の唯一の入口が year≤2022 に絞る）。
- 開示: 設計前のデータ確認で、2017-22 候補全体の `settle_status` の件数（win/lose の総数）を 1 回だけ画面に出した。
  合成にも判定にも使わない。

## 2. 合成の払戻

- 当たれば払戻 = `odds_decision` × 100 円（複勝は判断時点の幅の中央 = `odds_decision`）、外れは 0。
- 真の当たり確率 π:
  - 基本（市場が正しい世界）: π = (1 − 控除率)/odds_decision。控除率は JRA 値（単勝・複勝 20%、馬連・ワイド 22.5%、
    馬単・三連複 25%、三連単 27.5%）。期待回収率は券種ごとに 72.5〜80%。
  - 埋め込み: 部分集合 S の券だけ π = boost/odds_decision（期待回収率 = boost）。
  - π の上限 0.97（120% 条件で 49 券が切り詰め）。単勝候補 3 頭の π 合計が 0.995 を超えるレースは按分（120% で 11R）。
- レース内の構造:
  - 単勝: 候補 3 頭＋「その他」から 1 頭だけが勝つカテゴリ抽選。
  - 複勝: 候補 3 頭は単勝候補と同じ馬（全レースで一致を確認）。単勝で勝った馬の複勝は必ず的中、他の馬は条件付き確率
    (π_複 − π_単)/(1 − π_単) で独立に的中（周辺確率 = π_複 を保つ。π_複 < π_単 の 20〜31 券だけ周辺が π_単 に持ち上がる）。
  - **馬連・ワイド・馬単・三連複・三連単は券ごとに独立のベルヌーイ（単純化）**。単勝・複勝の結果とも独立。
- 合成の種: **11, 22, 33** の 3 本。同じ種では 4 条件で同じ一様乱数を使う（共通乱数）。
- 副次の「新しい抽選」: 選択期間 2021-22 の結果だけを種 +1000（1011/1022/1033）で引き直し、同じ方策を評価
  （選択に使っていない結果での成績。主判定には使わない）。
- コード: `analysis/bet_decision_ai/learner_check/synth.py`。

## 3. 部分集合 S（観測できる特徴だけで決まる、固定）

S = { 券種 ∈ {単勝, 複勝} } ∩ { log_p_over_q ≥ 学習期間 2017-20 の券種別 60% 点（単勝 0.31199、複勝 0.21601）}
    ∩ { n_field_decision ≥ 12 }

- 全候補券の **4.51%**（年別 4.27〜4.76%）、単勝 19,599 券・複勝 19,979 券、S の券を含むレースは 72.3%。
- 依頼の例（単勝・上位 20%・12 頭以上）は全候補の約 1.1% で 3〜10% に届かないため、複勝を加え上位 40% に広げた。
- 4 条件: 対照（埋め込み無し）、105%、110%、120%。

## 4. 検出力（学習器を動かす前に、ラベル・合成抽選なしで解析計算、`out/power_analysis.json`）

神託 = S と真の確率を知り、S の単勝・複勝（最大 6 券）への配分を E[log(1+κΣs(R−1))] 最大（Σs≤1）で求める方策。
選択期間 6,659R での期待平均対数成長と標準誤差:

| 条件 | 神託の期待対数成長 | SE | z | 購入レース率 |
|---|---|---|---|---|
| 対照 | 0 | 0 | — | 0% |
| 105% | 0.000819 | 0.000390 | 2.10 | 71.8% |
| 110% | 0.002315 | 0.000525 | 4.41 | 71.8% |
| 120% | 0.005675 | 0.000620 | 9.15 | 71.8% |

→ 110% で CI 下限 > 0 を出すには、学習器は神託の対数成長のおおむね 45% 以上を取る必要がある（120% は約 25%）。

## 5. 学習器（v1 と同じ、コードを変えずに import）

- NN: `train.NN_GRID`（v1 本番の 16 設定: softmax_abstain 4・sigmoid_ticket 4・relu_st 8、最大 60 エポック、patience 8、
  バッチ 512）。`policy.train_nn` で種 0 のグリッドを回し、選択期間の平均対数成長（連続の割合）が最大の設定を選ぶ →
  その設定で種 0-4 を学習 → **5 本の賭け金平均を主方策**（v1 の主の数値と同じ作り方）。
- GBM: `train.GBM_GRID`（12 設定）・`GBM_FIXED`・`train.gbm_fit`/`gbm_pred`・`policy.gbm_stakes`。選択期間の平均対数成長で
  設定を選び、種 0-4 の賭け金平均を主方策。
- 学習 2017-20 → 選択 2021-22。v1 の B4（市場版）はこの検証の対象外。
- 評価は v1 と同じ 100 円丸め（B = 10,000 円、`evaluate.round_stakes`）、CI は開催日ブロック bootstrap 4,000 回（`evaluate.metrics`）。

## 6. 判定量（選択期間 2021-22 の合成データ、条件 × 合成の種 × 学習器）

1. 平均対数成長（見送り = 0 との差）と 95% CI
2. 賭け金の部分集合集中度 = S の券への賭け金 ÷ 全賭け金
3. 回収率（合成払戻 ÷ 賭け金）、購入レース数・率
4. 神託の対数成長（同じ合成結果、同じ丸め）に対する比
5. 副次: 新しい抽選での 1〜4、学習期間（in-sample）の対数成長、種ごとの NN、グリッド全設定の履歴

## 7. 合格基準（固定）

学習器（NN、GBM を別々に判定）ごとに:

- **110% と 120% の両条件で**、合成の種 3 本中 2 本以上で「選択期間の平均対数成長の 95% CI 下限 > 0」かつ
  「賭け金の 50% 以上が S」。
- **対照**で、種 3 本中 2 本以上で購入レースが選択期間の全レースの 5% 以下。
- 上の全部を満たせば **合格**。どれか欠ければ **不合格**。105% は記述のみ。
- 神託自体の CI 下限が 0 以下になった種は、その条件で検出力不足として分母から外す（分母が 2 未満の条件は判定不能）。
- 主判定は 5 本平均の方策。種 0 グリッド最良・種ごとの値は記述。

## 8. 不合格のときの診断と修正（事前に決める手順）

- 診断: 学習期間 in-sample の対数成長が正になったか、エポックごとの賭け金と対数成長、初期状態での S と非 S への勾配、
  選ばれたエポック（0 = 学習前の状態が選ばれた）を見て、「勾配が流れない」「初期値で潰れる」「κ・L2・学習率」「配分の作り方」
  「早期打ち切り・選択規則」「GBM の目的（全額基準の対数効用）」のどれかを特定する。
- 修正版は v1 のコードを上書きせず `analysis/bet_decision_ai/learner_check/` に別ファイルで作り、同じ合成データで再検証する。
- 修正の過程で種 11/22/33 の合成結果を見るため、**修正版の最終確認は未使用の合成の種 44/55/66** で、§7 と同じ基準で行う。
- 実データでの再学習はしない（v2 の仕事）。v1 の判定は無修正の学習器の結果で決まる。
