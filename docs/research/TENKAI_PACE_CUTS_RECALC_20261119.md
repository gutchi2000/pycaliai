# 展開予想（tenkai）のペース区切りの再計算と新旧比較（2026-11-19）

> 位置づけ: `TENKAI_ACCURACY_2026_20261118.md` §5 の保守課題（ペースの区切り `meta.json cuts` が 2022 年までの三等分のまま）の分析。**本番には何も適用していない**（`tenkai.py`・`reports/tenkai/`・サイトは無変更）。
> 再現:
> ```
> python -m analysis.tenkai_pace_cuts build --root E:/PyCaLiAI --cache <scratch>/tkc   # 約 2 分
> python -m analysis.tenkai_pace_cuts eval  --root E:/PyCaLiAI --cache <scratch>/tkc --out <scratch>/tkc/result.json
> ```

## 0. 結論（先に）

- **区切りの再計算は適用しない方がよい。** 区切りだけを最近 3 年の三等分に変えると、同じ物差しで測って**どの物差しでも悪くなる**。2026 年の配信済み 1,966 R を JRDB 全頭再現の正解 B で測ると、Brier は 0.6187 → 0.6230（+0.0043 [+0.0015, +0.0070]）、ハイの予想は 42% → 54% のレースに増える（実際のハイは 32%）。
- 理由: **ペースモデルの予測値 μ は物差しのずれに付いていっていない**。tenkai 自身のペース値の年平均は 2020 年 7.6 → 2025 年 1.1 と動いたが、μ の年平均は 13 年間ずっと 3.4〜4.8 で平ら。区切りだけ下げると、μ はそのままなのでハイ側に倒れる。
- 区切り・σ・平均のずれを**まとめて**合わせ直す案（V3/V4）でも、現行（V0）より良くならない（B で +0.0013〜+0.0014、CI は 0 をわずかに外れて悪化側。的中率は同等）。2025 年での歩進検証でも、後知恵の「2025 自身の三等分」に対して −0.0008 [−0.0018, +0.0001] と差がない。
- 「ハイの割合が 33% → 24% に下がった」のは、**物差し（tenkai 自身のペース値）が周期的に動いている**ことの下降局面。旧区切りでのハイの割合は 2013 年 28% → 2020 年 40% → 2025 年 26% と上下している。物差しの基準タイムが「直前 5 年」で毎年入れ替わる作り（`speed_index.compute_figures`）なので、物差しそのものが動く。**JRDB 全頭再現の固定の物差し B で測ると、現行の確率は 2026 年も平均で合っている**（予測の平均 36/32/32% 対 実際 37/31/32%）。
- **「平均」が 35% を超えられないのは、区切りの問題ではない**。区切りを作り直しても上限は 0.344/0.351 → 0.349〜0.364 にしか動かない。原因は μ の分離力（μ と実際の順位相関は約 0.4、残差の標準偏差 16.5 が実際のばらつき 18 とほぼ同じ）。平均の当たり外れを μ で見分ける力（AUC）はどの案でも 0.51〜0.55 で、ほぼ無作為。
- **番手の相関と「届くか」は区切りを使わないので、どの案でも同じ**（2026 年 序盤 0.495 / 4 角 0.461、届くか AUC 0.663 のまま）。
- 推奨: **現行の区切りと σ を据え置き**、固定の物差し B での較正を年 1 回点検する（§7）。ハイ ≥55% の過信（2026 年 予測 60% / 実際 47%、n = 120）は区切りを変えても直らない。今の言葉の留保（ハイは最大でも「寄り」）を続け、標本が貯まってから見直す（CW-26）。

## 1. 何を比べたか

### tenkai の確率の作り方（`tenkai.py`）
ペースモデル（LightGBM 回帰、学習 〜2022）がレースごとに μ を出す。確率は、正規分布 N(μ, σ) を芝ダ別の区切り c1, c2 で切って作る。
P(スロー) = Φ((c1−μ)/σ)、P(ハイ) = 1 − Φ((c2−μ)/σ)。現行は c が ≤2022 年の三等分（芝 −4.39 / 10.66、ダ −1.49 / 13.89）、σ = 16.89（2023 年の残差の標準偏差）。

### 比べた案（モデル本体・位置モデルは触らず、確率への変換だけを作り直す）
| 案 | 区切り | σ | 平均のずれ（μ に足す） |
|---|---|---|---|
| **V0 現行** | ≤2022 の三等分 | 16.89 | なし |
| V1 | 窓の三等分 | 現行 | なし |
| V2 | 窓の三等分 | 窓の残差 SD | なし |
| V3 | 窓の三等分 | 窓の残差 SD | 窓の残差の平均（芝ダ別） |
| V4 | 窓の三等分 | 芝ダ別の残差 SD | 窓の残差の平均（芝ダ別） |

窓は「歩進検証」が 2023-24 年、「前向き」が 2023-25 年（参考に 2024-25 年・2025 年だけも）。V3 は区切りから平均のずれを引いた値を区切りにすれば同じになるので、`tenkai.py` を変えずに `meta.json` だけで表せる（§7）。

### 正解（同じ物差しで比べるため、区切りに依存しない物差しを主にした）
| 正解 | 中身 | 役割 |
|---|---|---|
| **B（主）** | JRDB SED 全頭から tenkai の定義を再現。コース基準・区切りは 2023-25 年に固定（`analysis/tenkai_accuracy_2026.py race_truth`） | 固定の物差し。どの案にも中立 |
| C | SRB のラップの前後半差（2023-25 のコース中央値・三等分） | 確認用 |
| A 旧区切り | tenkai 自身の値（`runs.parquet`）を ≤2022 の区切りで | 現行の定義そのもの |
| A 新区切り／窓区切り | 同じ値を窓の三等分で | 新しい案の定義そのもの |
| A 2025 自身の三等分 | 2025 年の値をその年の三等分で（後知恵） | 「今の物差しにぴったり合わせたら」の上限 |

- 2026 年の A は、週次出走表からの復元が頭数の 6 割以上あるレースだけ（1,136 R）。
- 2026 年の μ は、配信済みの `reports/tenkai/day_*.json` の確率から逆算した（現行の区切りと σ で確率に戻したときの最大誤差 0.001 ＝ 丸めの範囲）。
- 2013〜2025 年の μ は、学習と同じ作り方で各レースについて出し直した。**再現の確認**: ≤2022 の三等分は `meta.json` と完全に一致、2024-25 年の 3 区分の的中は 0.4557（meta 0.456）。

- **実際の値は 13 年で上下に 5 ほど揺れるが、μ は動かない。** 揺れはすべて残差の平均に出る。旧区切りでのハイの割合の「33% → 24%」は、2020 年の山（40%）からの下り坂の途中。

- 物差しが動く理由（推定）: `speed_index.compute_figures` は前半・上がりの基準タイムを「直前 5 年の良馬場・古馬 1〜2 勝の上位馬の中央値」で毎年作り直す。レースの形（前半と上がりの配分）の流行が基準から遅れて反映されるので、物差しの中心が周期的にずれる。μ の材料（過去走の前半の速さ）も同じ物差しの上にあるが、レース単位の「ペースの値」の中心の動きは学習できない（年の情報を持たない）。
- 固定の物差し B（2023-25 のコース基準）でも 2026 年はややスロー寄り（2023 年 33/33/35% → 2026 年 39/31/30%）だが、A の動きより小さい。

## 5. 「平均」の情報の薄さ

| | 現行 V0 | V1 | V2 | V3 | V4 | 参考: 25/50/25 |
|---|---|---|---|---|---|---|
| 平均の確率の上限 2Φ(w/2σ)−1（芝 / ダ） | 0.344 / 0.351 | 0.341 / 0.348 | 0.349 / 0.356 | 0.349 / 0.356 | 0.357 / 0.364 | 0.516 / 0.522 |
| 平均が最大になるレース（2026・B） | 8.0% | 3.8% | 8.7% | 8.1% | 8.3% | 80.7% |
| p(平均) の標準偏差 | 0.045 | 0.042 | 0.045 | 0.045 | 0.045 | 0.063 |
| AUC: p(平均) で「実際に平均」を見分ける | **0.523** | 0.514 | 0.515 | 0.517 | 0.519 | 0.535 |
| 参考 AUC: p(スロー) / p(ハイ) | 0.700 / 0.678 | 同 | 同 | 同 | 同 | 0.702 / 0.669 |

（上限は 2023-24 窓の値。2025 年窓の V4 でも最大 0.368）

- **区切りを作り直しても上限は 0.35 前後のまま**。上限は区切りの幅 w（芝ダとも約 15）と σ の比で決まり、w は実際のばらつき（SD 約 18）の三等分、σ は μ で説明しきれない残り（約 16.5）。μ と実際の相関が約 0.4 なので σ ≈ 0.91 × SD になり、上限は約 0.35 で止まる。上限を 0.5 にするには σ ≤ 11、つまり相関 0.79 程度が要る。
- 平均の当たり外れを μ で見分ける力は AUC 0.51〜0.54 でほぼ無作為。スローとハイ（0.68〜0.70）とは違い、**μ が真ん中にあることは「平均になりやすい」ことを意味しない**。両端に振れる確率が同じくらいという意味でしかない。
- 参考の 25/50/25（真ん中を広げる）は上限が 0.52 になり的中も 50.3% に上がるが、これは**定義の変更で、改善ではない**。実際の「平均」が 49% になり、81% のレースで「平均」と言うだけになる。いつも最多区分と言う基準に対する Brier の改善は、三等分の V0 が 6.9%（0.6647 → 0.6187）、25/50/25 が 5.4%（0.6306 → 0.5963）で、むしろ下がる。平均の見分け（AUC 0.535）も変わらない。
- 対応は今の表示どおり、**「平均が最大」は「読みにくい」と書き、根拠にしない**（2026-11-18 の留保、`zento` の `ペースを根拠にしてよい=false`）。仕組みで直すなら、レースごとに σ を変える（例: 先行馬の数がはっきりしているレースは σ を小さく）か、3 区分の分類器を直接学習する方向だが、AUC 0.52 を見る限り、「平均」で取れる情報はもともと少ない。V4（芝ダ別の σ）は効果なし。

## 6. 番手の相関と「届くか」

区切りは確率への変換にしか使わない。`tenkai.score_days` では、序盤・4 角の予想位置（pe / pl）は位置モデル、予想脚質（st）はその順位から、「届くか」（late）は close_model に μ を入れて出す。どれも区切りを通らないので、**どの案でも値は同じ**（2026 年 04-18〜11-14: 序盤の順位相関 0.495、4 角 0.461、予想 1 番手が 3 番手以内 65.1%、届くか AUC 0.663。`TENKAI_ACCURACY_2026_20261118.md` §3.2-3.3）。

## 7. 推奨

### 今は適用しない（据え置き）
- V1・V2（区切りだけ・区切り+σ）: どの物差しでも悪化。**採らない**。
- V3・V4（区切り+σ+平均のずれ）: 現行と差がない（B で +0.0013〜+0.0014）。切り替えると、過去の表示・展開タブの実績・言葉の目安を作り直す手間だけがかかる。**採らない**。
- 現行の区切りは物差し A の上では古いが、出している確率は固定の物差し B で合っている。このずれは、表示の言葉（「ハイは最大でも寄り」「平均は読みにくい」）で既に吸収している。

### 点検（年 1 回、または目に見えるずれが出たとき）
1. `python -m analysis.tenkai_pace_cuts build/eval` を回し、**固定の物差し B**（JRDB SED 全頭、2023-25 のコース基準）で 3 区分の確率の平均と実際の割合、ハイ ≥55% の帯、Brier を見る。
2. 作り直しを検討する目安: ある区分で「確率の平均 − 実際」が 5pt を超える状態が 500 R 以上続く、またはスロー/ハイの帯の較正が 2 帯以上で 8pt 以上ずれる。いまは最大 1pt（36/32/32 対 37/31/32）。
3. 作り直すときは**必ず V3 型**（区切り・σ・平均のずれを同じ窓で同時に）にする。区切りだけ（V1）は不可。採用条件は「直近の窓で作り、その後の期間を B で測った Brier の差の CI 上限が 0 未満」。

### もし作り直す場合の手順と影響範囲（将来用、今回は何もしていない）
- **値**: V3 は `meta.json` の `cuts` を「窓の三等分 − 窓の平均のずれ（芝ダ別）」に、`sigma` を窓の残差 SD に置き換えるだけで表せる（`pace_probs` は (c − μ)/σ しか見ないので、`tenkai.py` に平均のずれの項を足す必要はない）。2023-25 窓なら 芝 −4.94 / 9.53、ダ −2.03 / 13.05、σ 16.46（現行 芝 −4.39 / 10.66、ダ −1.49 / 13.89、σ 16.89）。V4 のように芝ダ別の σ にするなら `pace_probs` と `meta.json` の形が変わるので `tenkai.py` の改修が要る（効果は無いので不要）。
- **作り直す方法**: `tenkai.py train` は位置モデル・ペースモデルまで学習し直してしまうので使わない。区切りだけを書き換える小さなコマンドを足すか、手で `meta.json` を書き換える。`meta.json` の `test` 統計（pace_acc・pace_when_high・pace_calib）も新しい値で作り直す。
- **再採点**: `python tenkai.py score-days <起算日> <最終日>` で `reports/tenkai/day_*.json` を作り直す。**過去分は作り直さず、起算日以降だけ**にすると、2026 年の検証記録（`TENKAI_ACCURACY_2026_20261118.md`）と表示の履歴が混ざらない。`day_*.json` の `version` を新しい版に変える。
- **公開側**: `site/data/tenkai_meta.json`（`build_site.py` が展開タブの実績表示に使う）を更新し、`build_site.py` → `sync-hf-umami.ps1`（HF 同期はユーザー確認が要る）。
- **言葉の閾値**: `site/js/app.js`（展開タブ）・`worker/tools.js paceSummary / paceWords`・`zento_material.pace_summary` は確率に固定の閾値（50%、平均が最大）を当てるだけなので、コードはそのままでよい。ただし言葉ごとの実績（スロー公算 64% / ハイ公算 47% / 寄り 43〜44% / 平均 39%）は案ごとに変わるので、`TENKAI_ACCURACY` の表と展開タブの「的中の目安」を作り直す。worker を変えるなら `npx wrangler deploy`。
- **検証**: `validate_bets.py` のペースの検査（予想と違うペースの断定、ハイの強い断定）は zento.json の確率を読むので、コードの変更は不要。
- **影響しないもの**: 位置予想（pe/pl/st/先行勢/参考外の判定）、届くか（`close_model.txt`、`course_late_rate.json`、`close.edges`）。

### 根本の対策（別作業として検討する価値があるもの）
- 物差しが動く原因は、ペースの正解が「直前 5 年」の基準で毎年作り直される値であること。**ペースモデルの正解を固定のコース基準の物差し（B 型）に変えて学習し直す**と、区切りの保守自体が要らなくなる。ただし 2026-02-23 以降は全頭の走破がそろうのが JRDB SED だけ（`runs.parquet` は再出走馬だけの復元）なので、JRDB 由来の値を正解に使うことになる。確率だけを公開して JRDB の値そのものは出さない使い方（v7/v8 と同じ扱い）だが、規約の確認はユーザー判断。
- ハイ ≥55% の過信の見直しは、CW-26 で標本が貯まってから。

## 8. 注意
- 比較は 5 案 × 物差し 4〜5 × 期間 2〜3 の多重比較。「V1/V2 は悪化」は全部の物差し・期間・窓で同じ向きなので頑健。「V3 は差がない」の差（±0.002）は物差しによって向きが変わる。
- 2026 年の A は再出走馬だけからの復元（頭数の 6 割以上のレースに限った 1,136 R）で偏りがある。主の判定は全頭の B で行った。
- B の区切りも 2023-25 年の三等分なので、「最近 3 年の三等分」という点では新しい案と同じ考え方の物差し。それでも新しい案が勝たないのは、物差しの中心ではなく μ との位置関係が効いているから。
- 2026 年の μ は配信済みの確率からの逆算（11/16 に一括生成した as-of 予測。前日に保存した予測そのものではない）。
