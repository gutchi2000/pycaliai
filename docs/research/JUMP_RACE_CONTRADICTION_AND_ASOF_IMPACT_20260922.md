## 2. as-of 実 serve 影響率の再計算

### 2.1 方法

2026 年の serve 母集団（`data/weekly/2026*.csv` 全行 = **33,827 行 /
2,440 レース / 9,791 頭**）の各 horse-date について、
**判断時点より厳密に前（`date < race_date`）の履歴のみ**を使い、
欠落障害行を足した場合に `serve_history_feats.compute_row_feats()` の
出力が実際に変わるかを実測した。

馬の同定は production 自身が 2026 行に使うのと同じ名前ベース解決
（`_HistoryIndex.resolve()`）を用いた。欠落 598 行のうち
**580 行（97.0%）が ped_id に解決**（hit 580 / ambiguous 17 / new 1）、
unique 285 頭。

surface の扱いは契約により結果が変わるため 2 branch で測定した:
- **A**: 障害を独立 surface（`障`）として扱う
- **B**: master_v2 2013-2025 と同じく芝/ダへ recode（当該 serve 行の
  surface に一致させる**最悪ケース** = 影響の上限）

### 2.2 kako5 13 特徴は影響を受けない（実測確認）

TARGET の kako5 CSV の過去走スロットには **`TD='S'`（障害）が実在**する
（20260906/0912/0919 の 3 日で 74 件、距離 2750-3390m も確認）。
つまり **kako5_\* 13 特徴は障害走を既に見ており、weekly の障害除外の
影響を受けない**。影響するのは `_horse_history.parquet` 由来の
`serve_history_feats` 16 特徴のみ。

### 2.3 「影響馬候補」と「実際に特徴が変わる serve 行」

| 区分 | serve 行 | 対 serve 行 | serve レース | 対 serve レース | 馬 |
|---|---:|---:|---:|---:|---:|
| **影響馬候補**（as-of で欠落障害を保有） | **102** | **0.302%** | 51 | 2.09% | 82 |
| **実際に特徴が変わる**（branch A） | **80** | **0.236%** | 37 | 1.52% | 69 |
| **実際に特徴が変わる**（branch B = 上限） | **80** | **0.236%** | 37 | 1.52% | 69 |

branch A と B で行数・レース数・馬数は同一（B でのみ `hist_same_cond_*` が
1 件追加で変化する）。

### 2.4 どの特徴が変わったか

| 特徴 | branch A | branch B |
|---|---:|---:|
| `horse_fuku30` | 73 | 73 |
| `horse_fuku10` | 45 | 45 |

| `hist_same_cond_best_pos` | 0 | 1 |

| `hist_same_cond_count` | 0 | 1 |
| **`course_n_prev` / `course_win_rate` / `course_top3_rate`** | **0** | **0** |

surface が平地レースと一致しないため、平地 serve 行と同じ course バケットに

### 2.8 前回報告の訂正

`ALT_SOURCE_RECOVERY_AUDIT_20260922.md` §3 の

**as-of を取らず、かつ「実際に特徴が変わるか」を確認していない上限値**

serve 行すべてに波及しうる。**上限は serve 全行、下限は 0** で、現データでは
特定不能である。**§2.3 の 0.236% は「決定可能な特徴に限った下限」であり、
全体の影響率ではない。**

## 4. Shadow export feasibility — **未完了（共有状態への影響のため停止）**

32-bit Python（`py -3.12-32`）で JV-Link へ接続する shadow 専用プローブ
（`jvlink_shadow_probe.py`、書き出し先は
`analysis/mcond/p0_dnf_history_parity_audit/shadow/` のみ）を作成し、
欠落初期 `20260307` / 中央 `20260627` / 09-06 付近 `20260906` の 3 日を
対象に実行した。

**結果**:

| 項目 | 結果 |
|---|---|
| `JVInit("PyCaLiAI/1.0")` | **rc=0（OK）** — SDK・利用キー・契約はいずれも有効 |
| `JVOpen("RACE", "20260307000000", 4)` | **9 分以上ブロックし戻らず、こちらで停止した** |

**停止した理由**: JV-Link の蓄積系 `JVOpen` は、指定 fromtime 以降のデータを
**JV-Link のローカルデータストアへ一括ダウンロード（セットアップ）する**。
このローカルストアは **TARGET が共有して使う**ため、無断で走らせると
TARGET 側のデータ状態に影響しうる。これは「production を変更しない」という
本監査の制約を実質的に踏み越えるため、**ユーザー確認なしには実行しない**と
判断して停止した。

**確定したこと**:
- JV-Link の認証・契約は生きており、過去日データへのアクセス経路自体は存在する
- ただし取得は「1 レースだけ」では済まず、**期間一括のセットアップ**になる

**未確定（実行していないため不明）**:
race_id / 血統登録番号 / 芝ダ・障害区分 / 距離 / 騎手 / 調教師 / 血統 /
finish status / 取得時点 / 後知恵情報の有無 —— いずれも **未確認**。

**後知恵情報についての整理（実行前の設計上の区別）**:
- 過去日を今日再取得した値は、**当時の予測を再現する用途には使えない**
  （確定後の訂正・最終オッズ等が混入しうるため）
- 一方、**次走以降の履歴補修（着順・場所・距離・騎手・調教師）には使用可能**。
  これらは当該レース確定後に不変となる事実であり、次走時点では純粋に過去情報
  だからである
- ただしこの区別は「どの項目が後日訂正されうるか」を実データで確認して
  初めて確定できる。**現時点では未検証**

**次に必要な判断（ユーザー）**: JV-Link の期間一括セットアップを
走らせてよいか（TARGET の共有ローカルストアに影響しうる）。

## 5. 暫定方針への所見

第一候補 **P1** は、§1 の確定（**v6 は障害を学習している**）により
**論拠が強まった**。serve 側に障害履歴を足すことは、
「学習と serve の契約を揃える」方向であり、逸脱ではない。

ただし、ユーザーが提示した 6 条件のうち現時点の充足状況は:

| 条件 | 状態 |
|---|---|
| v6 の実学習に障害が含まれたか確定 | ✅ **確定**（train 14,716 行 / 1,267 レース、§1） |
| as-of 実影響率が確定 | ⚠ **部分確定**。決定可能分 **0.236% の serve 行**（§2.3）。ただし騎手・調教師系 7 特徴は**判定不能**で全体率は未確定（§2.9） |
| 安全な障害履歴取得元が確認済み | ❌ **未確認**。現アーカイブでは 2.68% しか復元できず、JV-Link 再取得は共有ストアへの影響判断待ち（§4） |
| prediction/betting 対象へ混入しない hard gate を設計 | ❌ 未着手 |
| shadow backfill で row/race/hash を検証 | ❌ 未着手（取得元未確定のため） |
| current artifacts を上書きしない | ✅ 本監査では一切上書きしていない |

**6 条件中 2 条件のみ充足、1 条件が部分充足。よって P1 の実装には着手しない。**
