# JRDB 成績ファイルの速報版／確定版のズレが配信の予測に与える影響（2026-11-19、分析のみ）

- 依頼: 手元の SED が速報版のまま残っている問題で、v8 の予測（勝率・順位・印）がどれだけ変わるかを測る。あわせて、学習データ側が確定版で作られているかを確定する。修正の是非はこの結果を見てユーザーが判断する（本番コードは変更していない）。
- スクリプト: `analysis/sed_prelim_impact.py`（`build` → `run` → `report`）。数値の正本: `SED_PRELIM_IMPACT_20261119.json`
- 作業データ（成績の表・作り直した bundle・ログ）は `data/jrdb/analysis/sed_prelim_impact/`（git 管理外。JRDB 由来のため）
- JRDB の項目の値は載せていない（規約）。載せているのは件数・割合・勝率の差だけ。

## 結論

1. **学習データ側は確定版で作られている。学習と配信の間にズレがある。**
   - 学習（2016〜22）・調整（2023）・test（2024〜25）の過去走は、JRDB の年単位ファイル（確定版）から作られている。IDM の空欄は年 3.7〜4.1% で、確定版の日別ファイル（2〜4%）と同じ水準。
   - 例外は 3 日だけ: 2022-08-27、2025-12-06、2025-12-07（下の「別件」）。その走を 1〜3 走前に持つ出走は、学習 0.17%・test 0.35%。
   - 配信側は 11/07・11/08・11/14 が速報版。速報版は着順・タイム・オッズはあるが、JRDB の指数・補正値（IDM、ペース指数、位置取り、不利、上昇度、クラスなど 23 項目）が全部空になっている。
   - そのため、過去走としては数えられるのに、特徴の中身が全部欠損になる。学習ではほぼ起きない入力の形で、学習と配信のズレは「ある」と確定。
2. **今の時点（11/14・11/15）では、v8 への影響は小さい。**
   - 69 レース 987 頭のうち、勝率が変わる馬は 1.2%（12 頭）。差の最大は 2.17pt。
   - 順位が変わる馬 0.2%、AI1 位・◎・印は 1 レースも変わらない。
   - 当時の本番だった v7 は影響が大きく、変わる馬 3.4%、差の最大 7.02pt。11/14 は ◎ が 2 レースで入れ替わっていた。
   - 影響が小さいのは、速報版が「先週末の 1 開催分」だけで、そこから中 1 週で走る馬が少ないため。
3. **直さないと、影響は週を追って大きくなる。**
   - 仕組み: 土曜の成績は土曜 19:40 のタスクが速報版のまま取り込み、以後取り直されない。日曜の分は金曜 19:40 に取るので確定版になる。
   - 放置した場合の見積もり（2025 年の出走間隔で推定）: 直前の走が速報版の馬は、4 週で 15%、8 週で 24%、13 週で 32%。
   - 同じ状況を表で作って v8 を走らせると、変わる馬は 4 週分で 17%、8 週分で 27%。印が変わるレースは 69 レース中 11 と 17。
   - 過去走特徴の埋まりは、4 週分で 66〜67%、8 週分で 57%、2026 年の土曜すべてで 44〜46%。50% を下回ると、本番の品質ゲートが v8 も v7 も止め、v6 へ戻る。
   - 見積もりでは、ゲートで止まるのは約 4〜5 か月後。それまでは止まらずに、ずれた予測が出続ける。

## 1. 何が違うのか（速報版と確定版）

11/07・11/08 は、手元の速報版と、控え（`data/jrdb/snapshots/Sed/`）に入った確定版を比べた。

| | 11/07 | 11/08 |
|---|---|---|
| 行数（速報版／確定版） | 501 / 501 | 497 / 497 |
| 速報版で空の項目 | 23 項目すべて 100% 空 | 同じ |
| 確定版の IDM の空 | 2.2% | 4.0% |
| 両方埋まっていて値が違う | 0（着順・タイム・オッズは一致） | 0 |
| 確定版の公開 | 11/12（木）11:30 頃 | 同じ |

- 空になるのは、IDM・素点・馬場差・ペース・出遅・位置取り・不利（前・中・後）・レース補正・コース取り・上昇度・クラス・馬体・気配・ペース区分・テン/上がり/ペース/レースペース指数・4 角コース取りの 23 項目。
- j1_* の 19 項目は、すべてこの中に入る。
- 速報版の行はあるので、過去走の順番はずれない。ずれるのは中身だけで、その走の 19 項目が全部欠損になる。近 5 走の IDM 平均・最大からも、その走が抜ける。

## 5. 限界

- 予測を比べたのは 2 日・69 レースだけ。速報版の影響の向きと大きさは測れるが、成績（◎の着など）の差は判断できない。
- C4・C8・C は仮想の表。速報版は「行はあり、23 項目が空」という形を 11/07・11/08 の 2 ファイルで確かめ、その形を土曜の確定版に当てはめた。実際の速報版が常にこの形かは、今後の控えで確かめる必要がある（控えには毎週、速報版と確定版の両方が入る）。
- 履歴・コード表などの他の入力は現在版を使った。全アームで同じなので差には効かない。

## 6. 別件（今回の範囲外、気づいたこと）

1. **`jrdb_parse.py` の重複の残し方**: 年単位 zip に同じ日のファイルが 2 本あると、ファイル名順で後ろ（`bk` 付き）が残る。2022-08-27 は速報版が学習に入っている（影響は学習の 0.17%）。
2. **JRDB の年単位ファイル自体に速報版が入る**: `SED_2025.zip` の 12-06・12-07。年単位に切り替えても直らない日がある。
3. **v8 の 11/14 の作り直しで品質ゲートが不合格になった**: KYI の上昇度の特徴（`k8_joushou`）の埋まりが 84%→0%。A・B・C のどれでも同じで、成績の表とは無関係。
   - KYI の発走前の控え（`KYI261114__20261113T194001.zip`）の上昇度は 87% 埋まっているので、特徴を作る段階で落ちている。
   - 原因は調べていない。11/15 は合格。v8 は 11/21 から本番。

## 7. 判断の材料（修正はしていない）

- 直すなら、`jrdb_fetch.py` の取得を「サーバーの更新時刻が手元より新しい日別ファイルは取り直す」にする（または、IDM が全行空の日別ファイルを取り直す）。そうすると、毎週金曜 19:40 の実行で前週の土曜分が確定版に置き換わる。
  - 最初の 1 回で 11/07・11/08・11/14 が確定版になり、配信の過去走特徴は学習と同じ形に戻る。
  - その翌日の予測は、上の A→B の分（v8 で 1〜数%の馬）だけ変わる。
- 直さない場合: 上の見積もりどおり、影響が週ごとに増える。約 4〜5 か月後には品質ゲートで v8・v7 が止まり、v6 で配信することになる。
- 前向き検証（CW-16・24・25）への影響: 11/19 から成績の控え（`scripts/jrdb_sed_snapshot.py`）が速報版と確定版の両方を残している。直した場合も直さない場合も、各開催日に配信が読んだ表は `asof` で引ける。直すと、修正日を境に配信の入力の形が変わるので、判定ではその日を区切りとして記録する必要がある。
