## 2. 学習器（仕様 v1.1 §10）

- 主の推定器: `model_v2.HuberDirect`（R − 1 を学習データの 1%/99% 点で打ち切り、Huber 損失 δ = 1.0 の LightGBM 回帰）。2 段は使わない。
- ハイパーパラメータ: `model_v2.GRID` の 12 候補から `model_v2.select_cfg_cv`。学習期間 2021-22 の開催日を 3 分割（分割の種は固定）、
  各分割で残り 2 つで学習し、保持側の R − 1（学習側の 1%/99% 点で打ち切り）に対する Huber 損失（δ = 1.0）を計算、全保持行の平均が最小の設定。
  2023 の合成結果は選択に使わない。
- 選んだ設定で開催日 bootstrap 10 本、控えめな採算 = 10 本の E[R] の下 20% 点、> 1.00 を 100 円で購入（v1.0 と同じ）。

## 3. 超過回収（§10 の新しい判定量）

- セル = 券種 × 判断時点オッズ十分位。判断時点オッズは単勝 = odds_tan、複勝 = odds_fuku_mid。十分位の境界は学習期間 2021-22 の全候補で券種ごとに決める
  （単勝 4.4 / 6.9 / 10.4 / 15.2 / 21.8 / 31.7 / 47.1 / 71.7 / 115.6、複勝 1.75 / 2.35 / 3.15 / 4.1 / 5.3 / 7.0 / 9.6 / 13.8 / 22.25。境界ちょうどは上の十分位）。
- 超過回収 = 購入券ごとの（R − 同じ評価期間・同じセルの全候補の平均 R）の購入平均。
- 95% CI: 開催日ブロック bootstrap 4,000 回。抽出ごとにセルの平均 R も抽出した開催日から作り直す。
- 設計値（真の期待回収率で計算、2023）: 対照ではセル平均 0.797〜0.800（どのセルも同じ）なので、どんな選び方でも真の超過回収 ≈ 0。
  S をすべて買ったときの真の超過回収は 110% で +0.264、120% で +0.351。

## 4. 合格基準（固定、仕様 v1.1 §10 §6-1）

- **対照**: 購入が 2023 の全候補の 1% 以下（922 件以下）、かつ超過回収の CI が 0 を含む。種 3 本すべて。
  購入 0 件なら超過回収は定義できないので「0 を含む」（勝ち筋の主張なし）として扱う。
- **110%・120%**（それぞれ）: 購入分の回収率の CI 下限 > 100%、購入の 50% 以上が S、超過回収の CI 下限 > 0。種 3 本中 2 本以上。
- 3 つすべてで合格。不合格なら実データに進まない。

## 5. 指標の確認（勝ち筋なしの世界で超過回収が 0 を含むか）

対照では購入が 0 件に近く、上の基準だけでは指標そのものを確かめられないので、各条件・各種で、控えめな採算の上位 1% と上位 5% を
強制的に「買った」とみなした超過回収と CI、真の超過回収（設計期待回収率 − セル平均）を記録する。
- **確認条件**: 対照の上位 1% 強制購入で、超過回収の CI が 0 を含むこと（種 3 本すべて）。
- これは学習器の合否ではなく指標の確認。満たさなければ、学習器の判定に関係なく実データに進まず、原因を報告する。
