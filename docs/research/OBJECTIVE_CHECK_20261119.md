## 結論（先に）

1. **目的関数は原因ではない**。同じ 120 特徴・同じ学習データで、勝敗を log-loss で直接学習したモデル（M1: 2 値、M2: レース内 softmax）も、現行スコアの温度スケーリングも、後半（774R）で現行の勝率と区別できない（LogLoss 差は −0.0006〜+0.0004、95%CI はすべて 0 をまたぐ）。
2. **市場との差は、どの作り方でもほぼ同じ大きさで残る**。後半の LogLoss の差は、最終市場に対して +0.017〜+0.018、T-10 市場に対して +0.014〜+0.015（すべて CI が 0 より上）。勝ち馬の対数尤度では 1 レースあたり 0.17〜0.22 nats 市場が良い。目的関数を変えて動く量（最大 0.007 nats/R）は、この差の 4% 程度。
3. オフライン（test 2024-25、6,909R）でも同じ: 2 値 log-loss の M1 は現行の作り方より**わずかに悪く**（勝ち馬 NLL +0.013 [+0.005, +0.021]）、M2 と温度は現行と区別できない（−0.003 前後、CI が 0 をまたぐ）。lambdarank → PL → isotonic という現行の作り方は、確率の当たり具合で損をしていない。
4. 温度は T = 0.913（1 未満＝現行スコアをわずかに尖らせる方向）で、点推定は 7 つの中で最良だが、現行との差は CI 内（LogLoss −0.0006 [−0.0014, +0.0001]）。
5. したがって「勝率が市場より平ら（解像度が低い）」のは、確率への変換や学習の目的関数ではなく、**特徴量に入っている情報の量**による、と読むのが自然。11/14 の検証で JRDB 由来の特徴（v7）だけが市場に微小な上乗せを示したことと整合する。
6. **副次的な所見（要確認）: 現行の勝率は一部の馬に確率 0 を付けている**。後半の勝ち馬 784 頭のうち 2 頭に、現行（再生）の勝率が 0.0000 だった（凍結版でも 2 頭が 0.001 未満、最小 0.0000）。配信用の isotonic 較正器が低いスコア帯を 0 に写すため。下限 0.001 を付けて測ると目立たないが、下限なしの勝ち馬 NLL では、この 2 頭だけで現行が他の作り方より 1 レースあたり約 0.05〜0.06 nats 悪く見える（温度との差 −0.060 [−0.147, +0.001]）。温度・M1・M2・市場は勝ち馬に 0.002 未満を付けていない。確率 0 は EV・組み合わせ確率の計算で「起こりえない」扱いになるので、下流での影響は別途確認が要る（本検証では直していない）。
7. 副次的な所見: 現在の配信経路で作り直した v6 の勝率（現行・再生）は、公開時点の凍結版より当たりが良い（LogLoss −0.0022 [−0.0043, −0.0002]、勝ち馬 NLL −0.028 [−0.052, −0.004]）。9〜11 月の配信経路の修正（serve 特徴の復元など）の効果とみられる。

## 6. 判断

- 「目的関数を log-loss に替える」「温度を合わせる」は、勝率の当たりをほとんど変えない。市場との差（勝ち馬 NLL で 0.17〜0.22 nats/R）は、作り方ではなく入力情報の差。
- 次に効きうるのは特徴（情報源）の側で、確率の作り方の側ではない。11/14 の JRDB の結果（v7＋市場が市場単独を微小に上回る）と、本番が v8（JRDB 前日 KYI）に移ったことは、この方向と一致する。v8 の前向き確認（CW-21）と CW-16 の 1,000R がその検証になる。

## 7. 限界

1. **検証期間の再利用**。後半（08-16〜11-15）は過去 5 本の分析と同じ期間。設計は結果を見る前に固定したが、厳密な意味で未使用の検証ではない。
2. **世代**: 新モデルはすべて v6 の特徴・データで作り、2026 は現在の配信経路で再生した v6 の X で採点した。公開時の勝率（凍結版）は v6-C0・C1・v7 の混合で、参考として並べた。
3. **v8 は含まれていない**（JRDB の制約、§2）。v8 で同じことが成り立つかは未確認。
4. **最終オッズは市場に有利な条件**（締切までの全情報を含む）。T-10 市場を並べたが、実際の購入時点のオッズはさらに動く。
5. **再生の限界**: 騎手・調教師コード表などの補助ファイルは現在版。履歴は当日より前に切っているが、再生の X は公開当時の X と同一ではない（現行（再生）と凍結版の差がそれを示す）。
6. **ハイパラ**: M1・M2 は v6 の lambdarank 用に Optuna で選んだハイパラをそのまま使った（目的関数ごとの再探索はしていない）。再探索で縮む余地はあるが、オフラインの差の小ささ（±0.01 nats/R）からみて、市場との差（約 0.2 nats/R）を埋める大きさにはならないと考える。
7. 温度の fit は前半の 606R（T-10 オッズのあるレース）だけ。
8. 勝ち馬 NLL の下限の扱いは事前に定めていなかった（§1 の注記）。両方を示した。
