# JRDB は締切時の市場が知らない情報か — 最初のゲート（2026-11-14）

きっかけ: ユーザー「新しい理論つくれないの？」。

## 理論

パリミュチュエルで控除を越えるには、締切時点の市場がまだ値段に入れていない情報が要る。
予測の数式を変える系統（9 月の DR-01A / PRED-01〜03、11 月の教師・目的関数・1着モデル・2 段構成）は、
すべて「同じ情報を並べ替えても市場は越えない」で終わった。v6 の 120 特徴を確定オッズに足しても、
勝ち馬の情報はほぼ増えなかった（`WIN_MODEL_EXP_20261113`、ΔNLL の CI が 0 を跨ぐ）。

このため、次に問うべきなのはモデルの形ではなく、入力が市場の外にあるかどうかになる。
v7（JRDB 過去走 59 列）は、それ以来はじめて入った新しい情報源にあたる。

## 方法

- 実装は `lab/experiments/v7_market_gate.py`、出力は `reports/v7_market_gate.json`。本番の pkl（v6・v7）をそのまま使い、再学習はしていない。
- 勝率はレース内 softmax(β·s) で出し、β は valid（2023 年）で推定した。市場の勝率は確定単勝オッズの逆数をレース内で正規化したもの（`kekka_1986_2025_enhanced.csv`）。
- 合成 log p = a·log p_model + b·log p_mkt を valid で fit し、test（2024-25 年、6,632R）で 1 回だけ評価した。CI は開催日単位の bootstrap（2,000 回）。
- 判定基準は事前に固定した。合格の条件は、「v7＋市場 − 市場」と「v7＋市場 − v6＋市場」の CI がどちらも 0 未満に収まること。

## 結果（勝ち馬 NLL、nats/レース）

| 比較 | ΔNLL | CI95 |
|---|---|---|
| v6 単独 − 市場 | +0.155 | [+0.143, +0.167] |
| v7 単独 − 市場 | +0.125 | [+0.113, +0.136] |
| v7 単独 − v6 単独 | −0.030 | [−0.038, −0.023] |
| v6＋市場 − 市場 | −0.00007 | [−0.00100, +0.00083] |
| **v7＋市場 − 市場** | **−0.00085** | **[−0.00168, −0.00005]** |
| **v7＋市場 − v6＋市場** | **−0.00079** | **[−0.00123, −0.00037]** |

合成の重みは v6 が a=0.059、v7 が a=0.055 だった。β の尺度が違うため、a 同士を直接比べることはできない。

年別の内訳（判定には使っていない）:

- 2024 年: v7＋市場 − 市場は −0.00104、v7 − v6（いずれも市場と合成）は −0.00090
- 2025 年: 同じ順に −0.00065、−0.00066

どちらの年も同じ向きだった。

**判定: PASS。** 手元のモデルが確定オッズに対して勝ち馬の情報を上乗せし、それが統計的に検出できたのは今回がはじめてになる。v6 では検出できなかった。

## 読み方（重要）

- **量は非常に小さい。** 上乗せは 1 レースあたり 0.0009 nats ほどで、単勝の控除 20% を越えられる大きさではない。市場単独との差は v7 単独でも +0.125 あり、モデルは依然として市場よりずっと弱い。この結果は馬券の戦略を変えるものではなく、新しい理論の最初の一歩にとどまる。
- **後から書き換えられたデータの可能性。** `sed.parquet` は現在のスナップショットで、当時の市場が見ていた値とは限らない。JRDB が IDM などを後から改訂していれば、その分だけ上乗せが水増しされている（馬主列で起きた future overwrite と同じ形）。前向きに確かめるには、v7 の配信値と T-10 / 確定オッズを 2026-11-14 以降で蓄積する必要がある。
- test 2024-25 は過去の実験で何度も使っている。ただし今回の比較は 1 回だけで、判定基準も先に固定してある。
- CI の上端（−0.00005）は 0 にかなり近い。偶然の範囲をかろうじて外れた、という読み方が妥当。

## この理論の次の一手（候補）

1. 前向きの確認: 2026-11-14 以降の v7 配信値（凍結版 bundle）と確定オッズで、同じ合成 ΔNLL を測る。約 1,000R でゲートを判定できる。
2. 上乗せが集中する場所を探す: 本命-大穴帯・新馬・休み明けなど、市場が JRDB を織り込みにくい場所に偏っていれば、そこが情報の境界になる。ただし、ここから買い目の総当たりにつなげることは禁止。
3. 市場が見ていない情報源を増やす: JRDB の当日系（前日指数はオフライン A/B で +2.77pt）は、同じゲートで最初に測る候補になる。ただし公開時刻が締切より前でないと前向きには使えない。

## 追補: 上乗せはどこから来ているか（同日、記述のみ・判定には使っていない）

勝ち馬の属性で分解した（`by_winner`）。値は勝ち馬 NLL の差（v7＋市場 − v6＋市場）と CI95。

- **JRDB の前走データの有無（プラセボ確認）**
  - 前走データがある勝ち馬（5,766R）: −0.00091 [−0.00141, −0.00042]
  - 前走データがない勝ち馬（866R）: +0.00001 [−0.00086, +0.00087]
  - 上乗せは JRDB の列から来ており、ほかの差分から来ているのではない。
- **前走からの間隔**
  - 〜5 週: −0.00044 [−0.00107, +0.00025]
  - 6〜9 週: −0.00096 [−0.00207, +0.00004]
  - 10〜25 週: −0.00119 [−0.00213, −0.00030]
  - 26 週〜: −0.00577 [−0.00868, −0.00290]（n=143）
  - 初出走: +0.00008
  - 間隔が長いほど、v7 は v6 より良くなる。
- **ただし市場との比較**（v7＋市場 − 市場）では、10 週以上の区分は +0.002〜+0.005 で、市場の方が良い。
  - 長期休養明けで v7 が良くなるのは「v6 自身の休養明けへの弱さを JRDB が補った」ためで、「市場が古いレースの質を忘れている」証拠にはならない。
  - 「市場の記憶には半減期があり、データの記憶にはない」という仮説は、この分解では支持されなかった。
- 勝ち馬の属性で条件づけた「対市場」の差は、モデルの尖り方（本命寄りかどうか）を強く反映する。人気帯の分解（〜2.9 倍 −0.024 / 15 倍〜 +0.041）がその例。属性別の対市場値は情報量として読まない。
