# PyCaLiAI ズレ警告 — 実装前の検証仕様（Claudeへ渡す用）
作成: 2026-11-18 / 上流: ぐっち＋ニア / 状態: 決定済み（目的=両方の2層式、採用は結果を見てから2段階で決める）

## 目的
「モデル順位は低いのに他指標が突出している馬（ズレ馬）」が、実際に当たるのかを
印象や単一事例（2026-11-15 エリザベス女王杯 ラフターラインズ）ではなく、
凍結済みデータ全体で検証する。検証で残った条件だけを警告表示の候補にする。
**この検証が終わるまで、警告表示は実装しない。**

## 表示は2層式（2026-11-18 ぐっち決定：両方やる）
- **強層（当たる信号）:** 検証まで通過した条件だけ。「ズレ注目」のように強く表示する。買いの根拠に使ってよい層。
- **弱層（不確実性の旗）:** 指標同士・指標とモデルが大きく食い違うこと自体を表示する「要チェック」。これは当たる予測ではなく「モデルが割れている＝人間が見るべき」という意味で、文言もそのように書く。性能が未証明でも、意味を偽らなければ出してよい層。
- 強層に入らなかった条件が自動で弱層に入るわけではない。弱層は「食い違いの大きさ」で定義し、強層は「検証された性能」で定義する。定義が別であることを混同しない。

## 大原則
- 閾値・条件は結果を見る前にこの仕様で固定する。結果を見てから閾値を動かしたら、それは探索扱いとし、別期間で再検証する。
- 試した条件は、結果が悪かったものも含めて全部報告する（多重検定による偶然の当たりを防ぐ）。
- 「当たる（勝率・複勝率）」と「儲かる（回収率）」は分けて報告する。
- 回収率に使うオッズの出所（朝9時／最終／サイト推定など）を必ず明記する。凍結JSONに無いオッズで計算した場合はその旨を書く。

## データ
- 主対象: サイトに凍結保存された発走前データ（2026-04-18〜、HONEST RECORD対象の1,943R範囲）とその結果。
- 期間分割（時間順）: 前半を発見期間、後半を検証期間として分け、両方で別々に集計する。両期間で同じ方向の結果が出た条件だけを採用候補にする。
- 除外: 障害、◎なし、発売前取消（HONEST RECORDの既存ルールに合わせる）。

## 事前登録するズレ条件（これ以外は今回試さない）
対照群は「同じモデル順位帯で、どの条件にも当てはまらない馬」。

- D1 馬レベル順位: モデル6位以下 かつ 馬レベル順位がレース内3位以内
- D2 馬レベル絶対値: モデル6位以下 かつ 馬レベル >= 90
- D3 PW: モデル6位以下 かつ PW順位1位
- D4 速度: モデル6位以下 かつ スピード指数順位1位
- D5 出世予測: モデル6位以下 かつ 重賞掲示板確率 >= 50%（重賞のみ対象、nが小さい前提で報告）
- D6 複合: モデル6位以下 かつ D1〜D5のうち2つ以上に該当

## 集計単位・層別
- 各条件 × モデル順位帯（6-8位 / 9-12位 / 13位以下）で集計する。
- D5のみ、クラス層別（重賞 / 非重賞）も出す。

## 出力（条件ごとに1行、発見期間・検証期間を別表で）
| 列 | 内容 |
|---|---|
| n_horses / n_races | 該当頭数・該当レース数 |
| win_rate / place_rate | 勝率・複勝率（Wilson 95% CI付き） |
| win_roi / place_roi | 単勝・複勝回収率（オッズ出所を注記） |
| lift_place | 対照群（同順位帯）に対する複勝率の比 |
| control_place_rate | 対照群の複勝率 |

## 採用の決め方（2026-11-18 ぐっち提案を、安全な形に直したもの）
「目安を先に固定せず、まず結果を出してから採用を決める」方式にする。ただし結果の見方を2段階に分ける：

1. **第1段階（発見期間だけ見る）:** Claudeにはまず発見期間の表だけを出してもらう。その結果を見て、強層の候補条件と採用目安（n・lift・回収率）をぐっち＋ニアで決め、このファイルに追記して固定する。
2. **第2段階（検証期間で確認）:** 固定した候補・目安のまま、検証期間の表を出してもらう。通過した条件だけが強層。
- もし発見／検証を分けずに全期間の結果を先に見てしまった場合、その条件は「探索で見つけた仮説」扱いとし、強層への採用は 2026-11-21 のv8本番開始以降の前向き検証（prospective）を通過してからにする。それまでは弱層表示まで。
- 注意：凍結サイトデータ（2026-04-18〜）はモデル世代 v5〜v7 の混在であり、v8そのもののズレ性能ではない。したがって強層の最終確認は、いずれにせよv8の前向きデータが要る。

### 強層の採用目安（第1段階で決める際のたたき台）
- 検証期間で n_horses >= 150（D5は重賞限定のため別途相談）
- lift_place >= 1.25 かつ 複勝率のWilson下限が対照群の複勝率を上回る
- 発見期間でも lift_place > 1.0（方向が逆転していない）

## 未決定事項

- 第1段階の結果を見たあとの、強層の採用目安の最終値。

## 第1段階の実施記録（Claude, 2026-11-18）

結果は `docs/research/ZURE_VALIDATION_PHASE1_20261118.md`。集計は `python -m analysis.zure_validation`（発見期間だけ）。
検証期間は `--phase validation --criteria-fixed` を付けないと出ない作りにしてあり、**まだ一度も集計していない**。

運用上の定義（仕様に書いていなかった部分。第 2 段階もこのまま使う）:
- 分割日: 対象 1,943R（2026-04-18〜11-15、障害 9R と◎発売前取消 4R を除外）を日付順に並べ、累計が半分に達した開催日まで＝**発見期間 2026-04-18〜07-26（994R）**、検証期間 2026-08-01〜11-15（949R）。
- 馬レベルは v5 期（04-18〜05-17、10 開催日 346R）の JSON に無い。D1/D2 が判定できず対照群も決まらないので、**全条件とも馬レベルのある日だけで集計**（発見期間では 05-23〜07-26 の 20 開催日 648R。初版の 586R は数え間違い、2026-11-18 訂正）。
- モデル順位はサイト掲載どおりの `ai_rank`。馬レベル・PW・スピード指数の順位は、発売前取消の馬を除いた出走馬の中で付け直す（同値は同順位）。
- D5 の「重賞掲示板確率」= 出世予測の `p_graded12`（サイトの表示名と同じ 1 年以内）。レース日より前の基準点のうち、予測窓（基準日 + 365 日）がまだ開いている最新のもの。出世予測の対象は 2023 年以降デビューの馬だけなので、古馬には値が無い（＝該当しない）。重賞 = クラス G1/G2/G3。
- 回収率: 確定払戻（`data/kekka/{date}.csv`、TARGET の結果 CSV）。公開 JSON には払戻が無い。1 頭 100 円の単勝・複勝。競走中止か発売後除外か区別できない馬（着順 0 で最終オッズあり）は回収率から外し、的中率では圏外。95% CI はレース単位の bootstrap。
- 対照群の複勝率は順位帯ごとに出し、「6位以下計」の行だけ該当馬の順位帯の構成で重み付けする。

## 第 2 段階の固定事項（2026-11-18 ぐっち決定、検証期間の集計前に追記）

1. **D3 の正式定義は D3'**: モデル 6 位以下 かつ PW 順位 1 位、ただし PW の同率 1 位が 2 頭以上いるレースは除く。新馬戦の全頭タイは定義バグの修正として扱う。
2. **強層候補は D1・D3'・D4 のみ**。D2・D6 は候補から外す。D5 は判定不能として弱層の参考に留める（表には出すが判定しない）。
3. **採用目安**: n ≥ 150 の足切りは廃止。主条件は「検証期間で lift_place ≥ 1.3、かつ 複勝率の Wilson 95% 下限が対照群の複勝率を上回る」。回収率は併記のみで、判定に使わない。
4. **v5 期は本検証に足さない**。今回は別表も作らない。
5. 検証期間のモデル世代の内訳を報告する。

細則（上の決定を集計に落とすときの解釈。Claude が追記、集計前に固定）:
- **判定に使う行は各条件の「6位以下計」**（対照は順位帯ごとの対照複勝率を該当馬の順位帯構成で重み付け）。順位帯別の行は記述のみ。
- **D3' を正式定義にしたので、対照群（D1〜D5 のどれにも当てはまらない馬）と D6 の「D1〜D5 のうち 2 つ以上」も D3' で数える**。第 1 段階の表は旧 D3（同率込み）で対照を作っていたため、新馬戦の 6 位以下の馬がほぼ対照から外れていた。第 2 段階では新馬戦の馬も対照に入る。第 1 段階の表は作り直さない。
- 旧 D3（同率込み）は検証期間では集計しない。
- 検証期間の集計は 1 回だけ。出力 `reports/zure_validation/validation.json` が既にあればスクリプトは止まる。
