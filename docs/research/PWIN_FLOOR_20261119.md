## 下限の値の選び方（既存の公開確率への影響を最小にする）

配信・学習用の較正器（isotonic）はすべて、最下段が 0 で、その次の段から正の値になる。0 でない最小出力:

| 較正器 | 単勝の 0 でない最小出力 | 複勝の 0 でない最小出力 |
|---|---:|---:|
| pl_calibrators_v6_serve（v6 の配信用） | 0.00255 | 0.00562 |
| pl_calibrators_v6 | 0.00123 | 0.00493 |
| pl_calibrators_v7 | 0.00157 | 0.00434 |
| pl_calibrators_v7_serve | 0.00375 | 0.00243 |
| pl_calibrators_v8（v8 の配信用、11/21〜本番） | **0.00086** | 0.00380 |

下限をこれらすべてより小さく取れば、変わるのは「今まで 0 だった馬」だけになり、他の馬の値と順位は 1 頭も動かない。単勝は最小の 0.00086（v8）より小さい 0.0005、複勝は最小の 0.00243（v7_serve）より小さい 0.001 にした。公開値は小数 4 桁に丸めるので、0.0005 は 0 に丸まらない。凍結 bundle の公開値でも、0 でない最小値は勝率 0.0011・複勝率 0.0024 で、どちらも下限より大きい。

この下限は**較正された推定値ではない**。凍結 bundle で勝率 0 だった 450 頭のうち 2 頭が 1 着（約 0.4%、95% 区間はおよそ 0.05〜1.6%）で、実際の勝率は下限より高い可能性がある。目的は「起こりえない（0）」と読まれる値をなくすことに限り、既存の公開値を動かさないことを優先した。較正そのものを直す（最下段に 0 でない値を入れて fit し直す）のは、較正器の作り直しになるので今回の範囲外。

## 他の確率・判定への波及

| 対象 | 波及 | 理由 |
|---|---|---|
| 混戦度（`race_confidence.field_chaos_score` → `chaos_pct`、参戦ガード） | **なし** | 下限は馬ごとの公開値にだけ入れ、混戦度のエントロピーは下限前のベクトルで計算する。下限を入れたベクトルで計算すると、0 の馬が計算に入って混戦度が動き、参戦ガードの分位（`data/chaos_quantiles.json`）とずれるため、あえて分けた。テストで確認 |
| 連対率 `p_plc` | なし | PL の重み（較正前、常に正）から計算 |
| 印馬ペアの組み合わせ確率 `pair_probs`（ワイド・馬連・馬単） | なし（変更していない） | PL の重みから計算し、組み合わせ用の較正器を通す別経路。凍結 bundle 14,080 組のうち 1 組に 0 があった。今回は勝率・複勝率の範囲に限り、ここは触っていない |
| 妙味判定（`betting_judgment`） | なし | 勝率 0.05 未満は候補外（`VALUE_PWIN_MIN`）。下限の 0.0005 は対象外のまま |
| a95 本線・T-20 の買い目 | なし | 勝率の上位馬を使う。下限の馬は最下位のまま |
| T-10 補正印・朝の補正印（`log p_win + λ log π`） | 実質なし | 今は勝率 0 の馬を順位付けから外している。下限後は最下位として入るが、印は上位 5 頭なので、勝率が正の馬が 5 頭未満のレースでだけ変わりうる。凍結 1,722R で該当 0 |
| 公開サイト・相談 AI などの表示 | 0.0% → 0.05% 等の表示 | bundle の値をそのまま表示するため |
