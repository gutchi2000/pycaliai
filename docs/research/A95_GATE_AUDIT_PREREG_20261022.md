# a95 500R 判定ゲート監査（M-1）— 計算前の宣言

**固定日時**: 2026-10-22 JST（この文書は計算を始める前に書いた。以後、本文は変更しない。結果は別文書
`docs/research/A95_GATE_AUDIT_20261022.md` に書く）
**対象**: P2-A95-EQUAL-LIVE-2026（本線 CW-11）と紙上台帳 CW-10 の 500R 判定ゲート
**種別**: label-free の監査（前向き cohort の的中・払戻・着順は一切開かない）。研究候補 M-1。

## 1. 変えないもの（凍結のまま）

- 判定規則: 有効 500R 到達時、レース的中率の片側 95% 上限（`shadow_a95.py` の iid 二項 SE、`hit + 1.645·√(hit(1−hit)/n)`）が床未満なら棄却。
- 床: 19.7%（`data/shadow_policies/a95_equal_v1.json` の `reject_if_hit_upper_below`）。
- n: 500（`min_valid_races`）。
- 方策（帯・券種・配分・参戦ガード）、`shadow_a95.py` の判定ロジック、policy sha256。
- この監査はどれも変えない。提案があっても文書に書くだけで、凍結物にも本番ファイルにも触れない。

## 2. 事前に決めた唯一の追加ルール

- 2023-2025 の歴史 substrate で推定した design effect（deff。500R・実際の開催日／開催日×場の
  クラスタ構成で計算）が **1.2 を超えたら**、500R 判定時に「deff 補正後の片側 95% 上限
  `hit + 1.645·√(deff·hit(1−hit)/n)`」を **併記する**。
- 併記は情報であり、判定ではない。棄却/非棄却の判定は §1 の凍結規則だけで行う。
- deff ≤ 1.2 なら併記は不要とし、その旨だけ記録する。
- deff は CW-10（全レース）と CW-11（参戦ガード通過）で別々に出し、それぞれの台帳に対応する値を使う。
  二つのクラスタ定義（開催日、開催日×場）のうち **大きい方の deff** を採用する（保守側）。

## 3. 計算する内容（label-free の範囲）

1. 歴史 substrate（`data/_policy/bet_substrate.pkl`、2023-25 OOS）で a95 の「レース的中」指標
   （凍結 plan の採用券種のどれかが当たる。枠連は 9 頭以上のみ）の ICC を、開催日と開催日×場で推定し、
   500R の実クラスタ構成での deff を出す。歴史データの的中は使ってよい（前向き cohort ではない）。
2. 帯構成のずれ: 「全レース × 9 時オッズ帯」と「参戦ガード通過 × 発走約 30 分前スナップ帯
   （historical_pre_snapshot、T-10 に最も近い歴史時点）」で、帯構成比と期待的中率を出す。
3. 2026-10 以降の前向き決定ファイルは **band 列の構成比だけ** を数える。的中・払戻・着順・決済ファイルは開かない。
4. 検出力: 真の的中率 23.3% / 19.7% / 15% で、500R の棄却確率を iid と deff 補正の両方で出す。

## 4. 結果がどう出ても変えないこと

- 床 19.7% と n=500 は、帯構成のずれや deff の大きさにかかわらず変えない。
  床の意味のずれは「棄却されず／棄却」の解釈注記として文書化するだけ。
- 新しい床・新しい n が望ましいと分かっても、それは次の policy id（v2）の設計材料として書くだけ。
