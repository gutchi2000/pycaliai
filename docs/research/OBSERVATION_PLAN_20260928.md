### 2.3 区分対応表（stream 別）

- **RT 系（`JVRTOpen`）と蓄積系（`JVOpen("RACE")`）は別 stream として別々に同定する**。同じ区分番号でも stream が違えば別行にし、片方の実測をもう片方に流用しない。
- 対応表の列: stream / 区分 / 観測された `announced_at` の `scheduled_post` に対する相対時刻分布 / 発売フラグの値 / 全組価格面の hash / 次区分との一致率 / 払戻録との勝ち組一致率。
- **RT 系で区分 4 が同一 race・同一券種に 2 回現れた場合は、`announced_at` が遅い方を採用**し、早い方は `superseded` として raw を残す。
- **区分 4 が 0 回なら `final` 欠損**とし、その race は当該券種の有効 race から除外する（欠損理由を列に残す）。
- **`final` の認定はコード番号ではなく**、次の 3 条件で行う: (i) 全組価格面が揃っている（§3 Stage 0 (5) の完全性）、(ii) 次に観測された区分（蓄積系の確定録を含む）と全組一致、(iii) 勝ち組オッズ × 100 が払戻録と一致。3 条件を満たす録が複数あれば `announced_at` が最も遅いものを `final` とする。

## 3. `t2_candidate` 契約と Stage 0

**E1 新規列**: 各券種の全組オッズ at 約 T−2、券種別 `announced_at`、券種間時刻差、発売フラグ、票数計。
**E2 取得**: `t10.ps1` 系のレース毎タスクに T−2 トリガーを 1 本追加。0B31 / 0B32 / 0B33 / 0B34 / 0B35 を同一プロセスで連続取得。
**E3 kill switch**: 下記 Stage 0 のいずれかで不成立なら `t2_candidate` は契約から外し、`vote` を最後の観測断面とする。
**E4 遅延**: `final` は確定後（分〜時間単位）に取得する。`t2_candidate` から `final` までに価格が動く機構は「締切直前の資金流入」であり、この差そのものを Stage 0 で測る。
**E5**: 500R 項目ではない。2 開催日の Stage 0 だけで意思決定可能時点か判定する。

**Stage 0（最初の 2 開催日、結果・着順・払戻は読まない）**
1. **fetch 所要**: 券種別 `fetch_finished_at − fetch_started_at` の分布（中央値・p95）。5 spec 合計 p95 が 60 秒を超えるなら「同時取得」を名乗らず、券種別時刻を必須列にしたまま契約する。
2. **発表遅延**: 券種別 `fetch_finished_at − announced_at` の分布。p95 > 120 秒の券種は「T−2 では鮮度不足」と記録。
3. **IPAT 締切の実測**: 発売フラグが「発売中」から変わる最初の `announced_at` と、`scheduled_post` の差の分布。仮定値を書かず、この実測を締切の定義にする。`t2_candidate` の `announced_at` がこの締切より後なら、その録は「締切後価格」として別扱い。
4. **vote 断面との差**: 同一レース・同一組で `log(odds_t2 / odds_vote)` の分布。中央値と p95。差が測定誤差内なら `vote` で代替可能と判定。
5. **完全性**: 単勝 = 出走頭数、馬連・ワイド = C(n,2)、馬単 = n(n−1)、三連複 = C(n,3)、枠連ブロック = 枠数に応じた組数。不一致率 > 1% で契約不成立。取消レースで未発売組と取消馬の一致。
6. **並走成功率**: `t2_candidate` 取得、別 race の `t10` 取得、三連複 shadow の 3 者が同一時間帯（±30 秒）に重なった取得について、成功率（rc=0 かつ race_key_ok かつ 完全性通過）を単独取得の成功率と比較する。重なり時の成功率 < 95%、または発走時刻 `00:00` 型の破損が 1 件でも出たら、**単一プロセスのキュー直列化を先に実装**し、それまで T−2 を追加しない（EXP05-F で PowerShell 経由の連続アクセス破損を実測した前例あり）。
7. **既存断面との整合**: 同一 rid の `t10` / `vote` / `close_late` と policy stamp・sha256 が一致。

判定: 1〜7 を通過した場合のみ、`t2_candidate` を「意思決定可能時点の候補」から「意思決定可能時点」に格上げする提案をレビュアーへ出す。

## 4. `close_late` と `final` の Stage 0

**唯一の問い**: `close_late`（発走後約 1 分の RT 録）は `final`（区分 3/4 の確定録）と同一か。
**測定**（2 開催日、全券種、label-free）
- 完全一致率: 同一レース・同一券種で全組オッズが一致する割合。
- 差分分布: 不一致組の `log(odds_final / odds_close_late)` の分布（中央値、p5、p95、方向の偏り）。
- 区分の遷移: `close_late` の `kubun` と `final` の `kubun` の組み合わせ表を **RT 系・蓄積系で別々に**作る（§2.3）。`final` の認定は §2.3 の 3 条件で行い、区分番号だけでは認定しない。
- 勝ち組照合: `final` の勝ち組オッズ × 100 が払戻録（HR）と一致する割合（EXP 三連複 preflight の 574/574 と同じ検査を全券種へ）。
**判定**: 完全一致率 ≥ 99% なら `close_late` を「`final` の近似」と記録して両方保存を続ける。それ未満なら `close_late` を決済に使う既存分析（forward_price_eval 等）に「非確定価格」の注記を付け、決済参照は `final` に一本化する。

### 5.2 方策の事前固定（結果開封前に確定、以後変更しない）

設計書 §6 の目的関数（期待利益の線形最大化）は常に 1 点買いに縮退するため、次で置き換える。

| 制約 / 目的 | 定義 |
|---|---|
| 制約 1 | 各組の期待値 E = p_model(組) × odds(組) ≥ 1 |
| 制約 2 | 最悪ケース床: 選択集合のうち最安払戻組が的中した場合の回収率 ≥ 75%（= 三連複プール還元率） |
| 目的 | 制約 1・2 を満たす集合の中で、的中確率 Σ p_model(組) を最大化 |
| 同値規則 | 的中確率が同値の集合が複数ある場合のみ、Σ E の大きい方を採る |
| 価格の時点 | 候補選択と配分は `t10`（本番）または `t2_candidate`（§3 通過後）の価格で行い、決済は `final` |

### 5.2b 配分規則（事前固定）

| 規則 | 定義 |
|---|---|
| 等払戻配分 | 選択集合の各組 i に `b_i ∝ 1 / odds_i`。どの組が的中しても払戻額が等しい |
| 100 円格子 | `b_i` を 100 円単位に丸める。丸めで床を割る場合は最も p_model の小さい組から外す（§5.2 の同値規則とは独立） |
| 床の同値表現 | 等払戻配分では 回収率 = 1 / Σ(1/odds_i) なので、**床 75% ⇔ `Σ_i 1/odds_i ≤ 4/3`**。最悪ケース床の判定はこの不等式で行う |
| 初回パスの価格 | **生の T−10 odds をそのまま使う。§10 の機構により勝ち組の T−10 odds は `final` より高く出るため、初回パスの E と床判定は楽観側に偏る**。この偏りは記録し、補正しない |
| `O_low` の扱い | bucket 別の期待縮小率 `O_low` は、**500R 到達かつ各 bucket 100R 到達後の第 2 パスだけで使用**する。途中で切り替えない。第 1 パスと第 2 パスは別集計とし、混ぜない |

### 5.3 500R の固定（E5）

| 項目 | 固定内容 |
|---|---|
| 有効 race | 発売中、C(出走,3) 完全、`race_key_ok`、`t10` と `final` の両方が存在、同着なし（同着は別集計で記述のみ） |
| 唯一の問い | 事前固定方策の前向き回収率は、三連複プール還元率 75% を下回らないか |
| 否定基準 | 回収率の片側 95% 上限 < 75% → 方策は「プール内でランダム以下」として棄却 |
| 500R 検出力 | 1 レースあたり回収率の SD を σ とすると SE = σ/√500。σ は開封前に**市場 null シミュレーション**（Harville λ 補正 PL の代わりに `final` 市場含意確率で組を引き、方策の払戻分布を label-free に生成）で最初の 100R から固定する。暫定 σ = 1.2 なら SE = 5.4pt、棄却閾値は点推定 < 75 − 1.645×5.4 = 66.1%。**真の回収率 60% に対する棄却検出力 = Φ((66.1−60)/5.4) ≈ 0.87、70% に対して ≈ 0.26**（v2 の 0.99 は片側シフトを落とした誤り。v2.1 で訂正） |
| 肯定に必要な n | 回収率 > 100% を CI 下限で示すには、真値 105% で n ≈ 1,600（σ = 1.2）、真値 102% で n ≈ 10,000。**500R では肯定できない。500R は初回棄却専用** |

## 7. stake・容量・自分の投票によるオッズ変化
