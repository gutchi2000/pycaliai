# v8 の前向き判定の集計スクリプト（CW-24）— 使い方と動作確認

作成: 2026-11-19 / 道具の追加のみ（本番の挙動は変えていない）
スクリプト: `analysis/v8_forward_gate.py`（冒頭に使い方と判定規則）

## 何を出すか

1. **モデル単独 vs 市場**: v8 の勝率（凍結 bundle の p_win）の 2 値 LogLoss と勝ち馬 NLL を、T-10 市場・最終市場と比べた差と 95%CI（レース単位ブートストラップ 4,000 回）。
2. **自由 fit したブレンドの重み**: log p = a·log p_model + b·log q_T10（レース内 softmax）。(a, b) は開催日順で前半の日に fit し、後半の日で「ブレンド − T-10 市場」「ブレンド − 最終市場」を評価する。全期間で fit した重みも記述として出す。

## 事前に決めた判定（2026-11-19 固定）

| 段階 | 条件 | やること |
|---|---|---|
| 収集中 | 採点できたレース 200R 未満 | 数字は出るが読まない |
| 中間確認 | 200R 以上 | 数字を 1 回記述。判定しない |
| 本判定 | 1,000R 以上 | 後半の日で「ブレンド − T-10 市場」の勝ち馬 NLL の 95%CI 上限 < 0 なら **BLEND**（ブレンド側で買い方を設計）、それ以外は **MODEL_ONLY**（モデル側の改善のみ） |

- 比べる市場は購入時点に近い T-10（発走 5〜15 分前のスナップショット）。最終市場との差は診断として出すが、判定には使わない。
- 確率はすべて採点対象の馬（中止等でない・最終オッズと T-10 オッズあり）でレース内正規化し、[0.001, 0.999] に制限。T-10 オッズが 1 頭でも欠けるレースは外す。

## 使い方

```powershell
python -m analysis.v8_forward_gate
```
既定は v8、2026-11-21〜今日。v8 の凍結データが無いうちは `stage: NO_DATA` を返して終わる。

```powershell
python -m analysis.v8_forward_gate --eras v8 --since 20261121 --out-json reports/v8_forward_gate/latest.json
```
結果を JSON に残す。

```powershell
python -m analysis.v8_forward_gate --eras v6-C0,v6-C1,v7 --since 20260613 --until 20261115 --force-final
```
動作確認用（v6/v7 の凍結データで、レース数に関係なく本判定の形で出す）。

入力は自動で探す:
- 凍結 bundle `reports/cowork_input_frozen/{date}_bundle.json`（`.provenance.json` が発走前と確認済みのものだけ）。世代はモデルの sha256 で判定（`bundle_provenance.model_era`、v8 は登録済み）。
- `reports/zure_freeze/{date}.json` があれば、そこに記録された bundle の sha256 と凍結 bundle が一致するかを確認する（不一致は日付を報告。除外はしない）。11/21 の Phase A から作られる。
- T-10 オッズ: `data/forward_prices/{date}/*_t10_*.json.gz`（無ければ `reports/live_odds`、どちらも発走 5〜15 分前の値だけ）。
- 結果・最終単勝オッズ: `data/kekka/{date}.csv`。

## 動作確認（v6/v7 の凍結データ、2026-06-13〜11-15）

結果 JSON: `docs/research/V8_FORWARD_GATE_DRYRUN_V6V7_20261119.json`

| 項目 | 値 |
|---|---|
| 対象 | 1,383R・46 開催日（v6-C0 1,034・v6-C1 280・v7 69）。T-10 欠けで 25R 除外 |
| LogLoss | モデル 0.23474 / T-10 市場 0.21294 / 最終市場 0.20842 |
| モデル − T-10 市場 | LogLoss +0.0218 [+0.0187, +0.0249]、勝ち馬 NLL +0.250 [+0.217, +0.286] |
| モデル − 最終市場 | LogLoss +0.0263 [+0.0231, +0.0296]、勝ち馬 NLL +0.303 [+0.266, +0.338] |
| ブレンドの重み（前半 781R で fit） | a_model = 0.039、b_market = 1.064 |
| 後半 602R: ブレンド − T-10 市場 | LogLoss −0.00014 [−0.00081, +0.00053]、勝ち馬 NLL −0.0018 [−0.0086, +0.0051] |
| 後半: ブレンド − 最終市場 | 勝ち馬 NLL +0.046 [+0.027, +0.065] |
| 全期間で fit した重み（記述） | a_model = 0.018、b_market = 1.068 |
| 判定（`--force-final`） | **MODEL_ONLY**（CI 上限 +0.0051 ≥ 0） |

モデルの重みが小さい（0.02〜0.04）のは、11/14 の検証（2024-25、最適が約 0.06）や、T-10 ブレンドの検証（`T10_MARKET_BLEND_CHECK_20261118.md`、重み 0.05 で市場と区別できない）と同じ。v6/v7 では「市場に足せる情報は検出できない」が、この道具の想定どおりの出力になっている。

v7 だけ（11/14〜15、69R）で流すと `COLLECTING` になり、判定は出ない（確認済み）。

## 注意

- モデルの勝率は公開時点の凍結 bundle の値（下限を入れる前の bundle では 0 の馬がある。確率の下限 0.001 で扱う）。
- 2 開催日以上が無いと前半・後半に分けられない。後半の日数が少ないうちは CI が広い。
- 自動計数（`analysis/collection_wait_gate.py`）にはまだ登録していない。台帳 CW-24 の現在量は手で更新する。
