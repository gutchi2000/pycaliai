# 重賞プロトコル（jusho_protocol.py）

> 重賞＋オープン特別/L にフォーカスした **深掘り分析カードの標準手順**。
> 既存資産（v6印・PL確率・ELO/Glicko・脚質・馬場・調教・血統・コース傾向・確定オッズ）を
> leak-safe で1枚に統合し、**買い目・発信・回顧すべての共通土台**にする。
>
> 最終更新: 2026-06-22（v1 新設、explain_race.py を土台に重賞層を追加）

---

## 1. 目的とスコープ

- **目的**: 重賞の予想を「印だけ」でなく、能力(レーティング)・適性(血統/コース)・仕上げ(調教)・
  展開(脚質/トラックバイアス)・市場(オッズ/EV)を **一望できる1枚** に標準化する。
- **対象レース**: `クラス名 ∈ {Ｇ１, Ｇ２, Ｇ３, ＪＧ１, ＪＧ２, ＪＧ３, 重賞, OP(L), (L), ｵｰﾌﾟﾝ}`
  （＝重賞＋オープン特別/L。クラス名一発で判定。レース名パース不要）
- **位置づけ**: これは **理解・説明・発信の土台**であって、勝てる保証ではない。
  重賞は **市場が最もシャープ＝AIのエッジが構造的に最も薄い帯**（検証済）。
  カードは「なぜそう評価したか」を可視化するもので、儲けは betting/ops 層の規律で別途管理する。

## 2. カードの中身

`explain_race.py` の土台カード（印◎〇▲△／AI勝率・複勝圏／予想・基準・実オッズ／EV／
対戦ELO・Glicko(μ±RD)／脚質・位置取り／馬場(クッション・含水)／展開ペース）に、
**重賞プロトコルが上乗せする層**：

| 層 | 内容 | データ源（全て既存・leak-safe） |
|---|---|---|
| ① 調教 | 坂路4F時計・ラスト1F・追切何日前（field内の速い順◎）／WC5F | master `trnH_Time1/Lap1/days_ago`, `trnW_5F` |
| ② 血統 | 種牡馬・母父・父タイプ ＋ **当コース好調血統との一致**(勝率) | master 血統列 ＋ `course_trend.json` 好調血統_父 |
| ③ トラックバイアス | 当 場×芝ダ×距離区分 の **脚質ランク・好調枠番** | `course_trend.json`（重賞セルが薄ければ上位クラス傾向で代用） |
| ③' 馬場バイアス | **当日のクッション/含水率→前残り度・枠バイアス**（馬券構築の地図） | `data/baba_bias.json`（`build_baba_bias.py`生成）＋`baba_feats` |
| ④ 重賞文脈 | グレード(G1/G2/…)・レースレベル(ELO)・出走の厚み | master クラス名 ＋ elo_feats |

**③' 馬場バイアスの読み方（実測・10年）**: 芝は重い(低クッション)ほど前残り強化（前残り度+25.8pp）、軽い(高速)で差しやや台頭(+21.8pp)。芝は終始 内枠やや有利。ダートは全帯で前残り超優勢、**濡れる(高含水)ほど前で止まらず(+32.4pp)**、かつ**外枠有利(外-内+1.4〜+2.8pp)**。カードは当日値→該当帯を引き「前残り度・逃/先勝率・枠補正」を1行表示し、`build_jusho` が◎の脚質と噛み合わせて「馬券構築」ヒントを出す。
※この馬場バイアスは現象として実在するが約9割が市場に織り込み済み（[[project_baba_cushion_tested]]）。展開・軸/相手の地図として使い、単体の妙味とはみなさない。

- **調教の無効値ガード**: `trnH_days_ago` が 0〜30日外（古い記録）の馬は坂路を「-」表示にし、
  field内ランクからも除外（この一戦の仕上げでない値を出さない）。
- **トラックバイアスの代用注記**: 重賞は希少で当該セルが薄いことが多い。脚質バイアスはコース物性で
  概ねクラス非依存のため、**OP重賞>3勝>2勝>…の優先順で最も重賞に近い上位クラスのセル**を採用し、
  `(○○基準・全クラス傾向 nR)` と母数・出典を必ず明記する。血統だけは OP/重賞セルを優先。

## 3. 実行方法

```powershell
# cache 内の最新重賞（デモ）
PYTHONUTF8=1 .\venv311\Scripts\python.exe jusho_protocol.py

# rid 指定（例: 有馬記念2025）
PYTHONUTF8=1 .\venv311\Scripts\python.exe jusho_protocol.py 2025122806050811

# 日付指定（その日の重賞＋OP/L 全部）
PYTHONUTF8=1 .\venv311\Scripts\python.exe jusho_protocol.py 20251228
```

- 自然文解説（Ollama）は起動時のみ付く。不要/未起動なら `EXPLAIN_NO_LLM=1` でテンプレ表示。
- **出力**: `reports/jusho/{rid}.json`（構造化）＋ 標準出力カード。

## 4. 出力の使い道（共通土台）

`reports/jusho/{rid}.json` を起点に各レイヤーへ：

- **買い目**: 印・EV・トラックバイアス・調教◎を Cowork / compute_bets の判断材料に
  （重賞は券種・点数を絞り、資金規律は [[bet_tier_policy]] の枠運用で）。
- **発信**: `make_jusho_short.py` の重賞ナラティブに、調教・血統・コース傾向の一言を供給
  （オッズ・生タイムは喋らない方針は維持）。
- **回顧**: 確定後に印×着順を突合（カードに `result_for_demo` 同梱）。重賞の印精度を週次で追跡。

## 5. 限界・注意

- **WC調教は低カバレッジ**（27%、2021〜）。坂路は81%。無い馬は「-」。
- **トラックバイアスは上位クラス代用が多い**（重賞単独は母数不足）。母数(nR)と出典クラスを見て割引く。
- **重賞は市場最シャープ**。本プロトコルは分析の質を上げるが、控除率を超える保証はしない。
  数値の質（calibration）が効くのは Cowork の判断材料としてであり、機械買いで勝てる主張ではない。
- 当日情報（馬体重・最終オッズ）はカードに実オッズのみ流用。印生成は 9 時前データで leak-safe。

## 6. 関連

- 土台: `explain_race.py`（分析カード層）／`make_jusho_short.py`（重賞発信）
- データ生成: `generate_course_trend.py` → `data/course_trend.json`（脚質/枠/血統傾向）
- 調教: `parse_training.py` / `make_weekly_hosei.py`（trnH_*/trnW_* を master へ）
