## 0. 目的（最適化対象）

- **1日の回収率**のみ。120%超=上出来／100%超=合格／**80%=耐えた（負けではない）**。
- 控除床(≒80%)を「負け」と見ない＝**利益最大化でなく「最も負けへん線＋たまに上振れ」**。
- ⚠ 6/28 は ROI 142.9% だったが**分散の上振れ**であって、このロジックが控除壁を超える証明ではない。
  目的は「君の良い判断を全レースで再現＋人間のミス/疲労/目算を排除」。

## 2. Step1 — バイアス（v0.2 で実装と整合化）

思想（本人ヒアリング）は「枠×脚質のバイアス適合で格上げ/割引」だが、**スコア再重み
(apply_bias) は v0.2 で撤去**した。根拠:
- クロスデイ馬場バイアスの**馬券効果は実測ゼロ**（日曜期待前馬 複勝ROI 75.9% ≒ baseline、
  [[project_crossday_trackbias_dead]]）。読み（前残り持続 Spearman+0.36）は本物だが換金不能。
- 実装上もスコアを動かすと混戦/クラスター判定が壊れる（クラスター判定は**生AI指数**が制約）。

**生き残ったバイアスの効き先**（コードに実在する経路のみ）:
1. **逆風フラグ** — ◎が後脚質 × 前残り日 → 券種形を軽くする（三連複カット・ワイド流し広め）。
2. **バイアス記号ゲート**（`bias_mode=True` の opt-in）— ◎が有利脚質×有利枠(★)のレースだけ参加。
   決済実測でゲート ON が OFF を上回らず（データ枯渇 NO-OP 含む）**既定 OFF**。
- **脚質(前残り)＝最優先・不変** / **枠＝馬場で反転する弱信号**、の序列は逆風フラグに反映
  (脚質のみ見る。枠は使わない)。
- ⚠ 二重逆風での**◎軸降ろし→〇▲繰上げは未実装**（bias_symbol の ⚠振替は記号表示までで、
  構造判定を汚染するため軸には配線しない。再検討は前向きデータ n≥100 蓄積後）。

## 3. Step2 — 信頼できる頭数を数える（背骨の芯）

> **AI指数を上から見て、"連続する馬の落差"で区切る。** 落差 **~15〜18pt 以上＝「信頼の壁」**、そこで切る。
> 壁より上の固まり＝**信頼できる頭数**。

- 例: 福島7R 100→92(8pt 近い)→76(16pt 離れ) ⇒ 〇で切って**2頭**。
- 例: 小倉3R 100→80(20pt)→79→79→75(団子) ⇒ ◎単独＋**下が団子**。
- **穴すぎる相手は数えない**（高オッズの相手を増やすと人気リスクが複利で増える）。
- ⚠ ~15-18pt は **6/28一日からの目安**。複数日で較正すること。

出力: `1頭 / 2頭 / 3頭スパッと / ◎単独+団子 / 少頭数`

---

## 4. Step3 — 頭数 → 券種の形（決定木）

| 信頼グループ | 形 |
|---|---|
| **1頭**（◎のみ / ◎→〇が壁越え） | → 下記「単複判定」 |
| **2頭**（◎〇が近い） | 馬連(◎-〇) ＋ ワイド(◎-〇) |
| **3頭がスパッと割れ** | 馬連流し(◎-〇▲) ＋ ワイドBOX(◎〇▲) ＋ 三連複1点(◎〇▲) |
| **◎単独 ＋ 下が団子** | 馬連(◎-上位) ＋ ワイドBOX ＋ **三連複 ◎軸流し**（団子全部に・相手の穴が多いほど広げる） |
| **少頭数(≤5頭) × ◎確勝級** | 三連複(本線=◎込み) ＋ 上位4頭BOX（**三連単は禁止則で不使用**・2026-07-10撤廃済） |

### 1頭（相手なし）の単複判定 ★トリガミ床
- **複勝倍率(投票時) ≥ 1.5倍** → **単勝¥3,000 ＋ 複勝¥7,000**
- **複勝倍率 < 1.5倍** → **複勝¥10,000 1点**（圧倒的人気。単複に割ると複勝側がトリガミ）
- 床の根拠: 複勝¥7,000 × 1.5 = ¥10,500 > ¥10,000 ＝ 複勝だけ当たっても元割れしない最低ライン。

## 5. 券種の役割（オーバーレイ）

| 券種 | 役割 |
|---|---|
| **ワイド** | **基軸**（ほぼ常設の安定・保険）。「いつも通りワイドに信頼を置く」 |
| **複勝** | ①確勝級◎の床(1.1倍でも確実拾い) ②突出∧穴の妙味拾い(3倍級) |
| **馬連** | 一撃upside。**馬連流し⇔三連複は本人の中で代替**（裁量）→ エンジンは**固定デフォルト** |
| **三連複** | spread。相手の穴が多いほど点数を広げる |
| **単勝** | ◎の**複勝≥1.5倍の時だけ**（単複 3000/7000） |
| 馬単 | **全廃** |
| 三連単 | **全面禁止**（旧: 少頭数例外 → 2026-07-10 撤廃、三連複に置換） |

## 6. Step4 — 予算・枠（[[project_bet_tier_policy]]）

## 7. 後処理（機械的）

- **取消**: 取消馬を含む買い目を自動除外。残りで確定（エンジンは取消後フィールドで構築）。
- **相手集合は券種間で統一**（馬連/ワイド/三連複の相手を揃える）。
- **流し vs BOX は想定払戻で最適化**（実オッズで計算）。

---

## 8. ★エンジンが人間を上回る点（6/28の実打で判明）

1. **押し間違いを起こさない**（小倉12R: ワイド相手=…11 / 三連複相手=…12 と取り違え）。→ 相手集合を統一。
2. **流し/BOX を実オッズの想定払戻で最適化**（小倉12R: 人間は目算で「BOXじゃなくてOK」）。
3. **疲労による逸脱を起こさない**（福島12R: 最終Rで力尽き、本来単複→複勝1点に縮めた）。→ ルール通り実行。

## 9. 未確定・要較正（v0は1日分の抽出）

- **信頼の壁 ~15-18pt** は 6/28 一日の目安。複数日で較正。
- **馬連流し⇔三連複の代替**は裁量 → v0は固定デフォルト（本人の好みで調整）。
- **バイアス再重みの強さ**（格上げ/割引で印やスコアを何pt動かすか）は未定量。

  [[project_longshot_weakness]] 的に ROI 注意（複勝で安全に拾う形なら可）。
- 検証は**前向き全打ログ + CLV + n≥100**（in-sample蜃気楼を避ける。[[project_gutchi_tactics_journal]]）。

## 10. 決定木サマリ（擬似コード, v0.2 実装準拠）

```
build_tickets(race):
    if 新馬: 見送り
    if chaos_percentile >= 0.667: 見送り            # ★参加ゲート(2026-07-31昇格): 構造分岐に関係なく冒頭で真の見送り
    # (bias_mode=True の時のみ) ◎が★でなければ見送り — 既定OFF
    n = count_trust(生AI指数, gap_wall≈15-18pt, drop_too_longshot)   # Step2 (biasでスコアは動かさない)
    if field_size <= 5 and ◎ 確勝級:
        return 三連複(本線=◎込み4割) + 上位4頭BOX   # 3頭立ては本線1点に全額。三連単は禁止則で不使用
    if ◎非分離 + 団子:
        return 上位N頭 ワイドBOX + 三連複BOX          # 予算は点数で使い切る
    if ◎逆風 (後脚質 on 前残り日):
        return ◎軸ワイド流し広め + ◎-〇▲馬連         # 三連複カット。ワイド:馬連=2:1 で予算按分
    if n == 1:                          # 相手なし
        return 単勝3000+複勝7000  if 複勝倍率>=1.5 and 単勝妙味帯  else 複勝10000
    if n == 2:
        return 馬連(◎-〇) + ワイド(◎-〇)              # 2頭圧倒なら ◎単+複両頭の保険形
    if n >= 3:
        return ワイドBOX(◎〇▲) + 馬連流し(◎-tight) + 三連複1点
    # --- L3 規律層 (_discipline, 2026-07-31 配線) ---
    トリガミ床(適応点数): 三連複ブロックを kstar=⌊0.775/p_fav⌋ 点まで削る (見送りでなく点数削り)
    chalk-cap: chaos < 0.86 (堅い) なら総点数 12 まで (低確率トリオ→末尾ワイドの順に落とす)
    apply 取消除外(scratched), tier予算(budget 引数)
```

## 11. v0.2 決済実測 (simulate_brain_day, 16開催512R, 2026-05〜07)

| 構成 | 参加R | ROI | 的中率 | 当ﾄﾘ率 | 最大DD |
|---|---|---|---|---|---|
| 旧v0 (ゲートは混戦枝内のみ) | 389 (76%) | 84.2% | — | — | — |
| ゲート無し (バグ修正のみ) | 469 (92%) | 76.4% | 52.9% | 46.0% | ¥1.09M |

- ROI 差は全て MDE(≈19-21pt) 未満で**判定不能**（SE≈7pt）。判定可能な主指標では
  ゲートが**的中 +4.4pt / トリガミ −3.1pt / 最大DD −36%** と選別ドクトリン通りに効く。
- 閾値感度 (0.88-0.97): ROI は 70-77% のノイズ帯、的中/トリガミ/DD は閾値を下げるほど単調改善。
  0.92 は旧監査時の事前固定値。現行policyは修理後serve凍結分布のp66.7（raw換算0.858108）へ別cohortとして移行。

### 厳選モード (opt-in, 2026-07-31 事前固定)

「もっと厳格に」の実測回答: v0.2 参加281Rを chaos×dom1×agreement の格子で更に絞っても
**ROI 点推定が 100% を超えるセルはゼロ**（最良 dom1≥0.10=86.9% / agr≥0.7=85.9%、締めすぎは
逆に悪化する非単調=ノイズ形。8Rまで絞った最厳格セルは48.6%）。厳格化で単調に改善するのは
生存指標のみ（DD ¥706k→¥74k、当ﾄﾘ 42.9%→0%）＝**厳格化は「負けない」レバー、「勝つ」レバーではない**。
- 実装: `build_tickets(strict=True)` = chaos<0.90 ∧ top1_dominance≥0.10 のみ参加。
  参照値 74R(~7R/日) / ROI 88.6% CI[62,118] / 当ﾄﾘ17.9% / DD¥135k。
- 有効化: simulate は `--strict`、T-10 は環境変数 `BRAIN_STRICT=1`（表示に[厳選]タグ）。
- **既定OFF**。この閾値は in-sample 選択なので、採否は前向き n≥100 + CLV で判定する。
- 旧v0 の混戦枝内ゲートが外していた ~80R は実測 ROI 43%（ゲート自体は有効）。逆に
  全レース昇格で追加に外れた ~108R はこの標本で ROI 111% = 高分散の上振れ源も削る。
  **選別は「儲け」でなく「負け最小化」レバー**という前提を忘れないこと。
