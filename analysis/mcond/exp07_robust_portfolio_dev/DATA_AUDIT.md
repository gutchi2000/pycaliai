## 5.3 時点安全性

| 確認項目 | 結果 |
|---|---|
| T-35/T-20/T-10のどれを判断時点とするか | **前向き(2026-08-29以降)はT-10固定**(`forward_price_protocol.md`)。過去(2024-2025)は後述5.4の通りT-28前後の代替のみ、真のT-10は存在しない |
| 判断時点より後のオッズ混入 | `forward_price_protocol.md`が「close価格や結果をdecision特徴へ逆流させることを禁止」と明記、既存プロトコルを継承すれば安全。EXP07独自の新規混入経路は候補生成・確率計算いずれも判断時点以前の情報のみで完結する設計とする(§7で担保) |
| 確定オッズを予測値として利用していないか | 現行SettleAIは確定オッズを「点補正の学習対象」としてのみ使用し、判断特徴には使っていない(EXP06期に既検証)。EXP07で新規に確定オッズを紛れ込ませる経路がないことをGate 0で確認する |
| 取消・騎手変更の判明時刻 | 前向き分は`jvlink_changes.py`で当日判明時刻が記録される(2026年分のみ)。過去分(2024-2025)は判明時刻の記録なし、最終的な着順NaNとしてのみ事後判別可能 |
| 確率較正器の学習期間 | `pl_calibrators_v6.pkl`はvalid=2023年でfit(CLAUDE.md記載の時系列分割: train≤2022-12-31, valid=2023, test=2024-01-01〜)。**2024-2025はcalibratorの学習に使われていないことを確認済み**（既存ドキュメントの記述通り、EXP07で新たに検証しない） |
| 候補生成コードの版 | v6本番の`export_weekly_marks.py`/`unified_rank_v6.pkl`のモデルハッシュで固定可能(§5.1)。EXP07独自の候補生成コード(ticket_key構築等)はこれから新規実装するため、当然ながら過去のいかなる時点にも「版」は存在しない(新規実装後にhashを取り、以後固定する) |
| OOF予測または完全OOS予測か | v6のtrain(〜2022)/valid(2023)/test(2024-2025)分割により、**2024-2025のv6スコアは完全OOS**(モデルはこの期間を学習に一切使っていない)。ただしEXP01-06のいずれかで2024-2025を「探索的OOS」として既に開封済みの経緯があるため、EXP07でも同じ位置づけ（探索的、完全未使用ではない）を踏襲し「完全未使用期間」とは呼ばない（絶対条件9） |
| 2024〜2025年学習モデルが混ざっていないか | v6は上記の通り2022年までの学習。ただしSettleAIの帯別補正表(n=742)は**2026-06-07以降のデータのみ**で構築されており、2024-2025評価にはSettleAI補正を使わない(較正なしのodds_floorで代替するか、5.4のTANPUK直接値を使う設計とする) |

## 5.4 過去再現性（2024〜2025年）

**結論: 真のT-10オッズによる過去再現は不可能。現在コードによるreplayとしてのみ評価できる。**

`data/Time _series_odds/TANPUK_20210105-20251228.csv`（区分1=前売り）の各レースにおける
**最終の前売りスナップショット**と、`master_v2`の実際の発走時刻を突き合わせて実測したところ
（2024-2025年、n=6,909レース、race_idで完全一致）:

| 統計量 | 発走前オフセット(分) |
|---|---|
| 平均 | 27.8 |
| 標準偏差 | 1.6 |
| 10%点 | 26 |
| 中央値 | 28 |
| 90%点 | 30 |

すなわち過去データで入手可能な「最も発走に近い」オッズスナップショットは**発走のおよそ26〜30分前
（中央値28分前）であり、T-10ではなくT-28相当**（既存ドキュメントが言う「T-35」帯にほぼ一致、
オフセットのばらつき自体は小さく規則的）。前向き収集（2026-08-29以降）が実現しているT-10取得
（`data/forward_prices/`, `reports/live_odds/`）とは異なる時点であることを明確に区別する。

**したがって**:
- 2024-2025年の評価は「T-28相当のTANPUKアーカイブ値を判断時点オッズとして使い、現行のPL確率
  計算コードと候補生成ロジックを**今のバージョンで**当てはめるreplay」としてのみ実施できる。
  これは**実際にその時点でJRA-VANから配信されたT-10オッズを使った実配信の再現ではない**
  （仕様書5.4の要求通り明記）。
- 馬連・三連複はforward_price_protocol.md自体が「有効なactual T-10価格がまだ0件」と明記して
  おり、2026年の前向き収集分についてすら単勝/複勝/ワイド/馬単のみがT-10実測を持つ。2024-2025年
  については単勝/複勝/ワイド/馬単もT-28相当の代替のみ、馬連・三連複はTANPUKアーカイブ自体に
  該当列がなく**過去データが存在しない**（`docs/plans/plan_scenario_crowd_divergence_trio.md`の
  Phase 0監査と同じ結論、EXP06監査時の未探索領域調査4.14で既出）。
- 前向き（2026-08-29以降）の真のT-10データは現時点で8開催日分のみ（`data/forward_prices/`の
  ディレクトリ数）、EXP07のStage 2A/2Bで統計的検出力を持つ規模ではない。

## まとめ（Stage 2Aへの申し送り）

- **development(2023)/exploratory test(2024)/exploratory confirmation(2025)はいずれも
  TANPUKアーカイブのT-28相当値を使ったreplayとして実施する**（真のT-10ではないと明記した
  分析として扱う）。
- **forward confirmation(2026年以降)は真のT-10データ(`data/forward_prices/`)を使うが、
  現時点でサンプル数が少なく(8開催日)、前向き確認は当面「配線検証のみ」の段階に留まる**
  （`docs/plans/exhaustive_betting_policy_verdict_20260825.md`の昇格ラダー方式を踏襲）。
- 対象券種は単勝・複勝・ワイド・馬単に限定する（馬連・三連複はデータ不在のため除外、
  仕様書4節「既存研究との差」が三連複を直接の検定対象に含めていないことと整合）。
- 同着・返還の決済ロジックは過去に誤りが実在した領域であり、EXP07独自のsettle実装
  （`evaluate.py`）はfail-closed設計とし、Stage 1合成テストで同着・返還ケースを個別に検証する
  （仕様書8節項目15）。
