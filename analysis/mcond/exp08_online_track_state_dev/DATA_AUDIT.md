## §5.2 利用可能時刻ルール(2023 developmentのみで固定)

**測定**: `master_v2`(split=valid=2023、n=3,456レース)の`発走時刻`と、TANPUK
`区分4`(確定)の最終タイムスタンプの差を実測。

```
count=3456  mean=7.30分  median=7分  90%点=9分  95%点=9分  99%点=13分  max=23分
```

（区分4は「確定オッズ」のタイムスタンプであり、確定オッズの算出には着順確定が
前提のため、このタイムスタンプは「結果が公式に確定した時刻」の妥当な代理指標。
2023年のみを使用、2024-2025は見ていない。）

**固定ルール(凍結)**:
```
prior_result_available_timestamp = actual_post_time + 15分
```
99%点(13分)に安全マージンを載せた15分を採用。審議(steward's inquiry)等で
23分かかった稀なケースは「まだ利用不可」として保守的に扱われる(item 5の
「結果利用可能時刻より前は更新されない」を満たす方向の保守性)。

対象レース自身の判断時点`decision_timestamp`は、EXP07で確立した
`historical_pre_snapshot`(TANPUK区分1最終、発走26-30分前・中央値28分前)を再利用する。
したがって、ある先行レースが対象レースに使えるのは：

```
先行レースの実発走時刻 + 15分 <= 対象レースの発走時刻 - 28分(中央値、実際は区分1最終の実測時刻)
```

これは実務上、対象レースの発走の43分以上前に発走を終えている先行レースのみが
使える、という保守的な境界になる。レース番号だけでは判定しない(仕様書の禁止事項通り、
実際の発走時刻同士で判定する)。

## §6 事前期待値モデル: 時計(走破タイム)残差の時点安全な構築が必要

EXP08§6/§7.3は「同条件の期待走破タイムに対する残差」を要求し、「期待タイムモデルが
時点安全に構築できない場合、この状態次元は除外する」と明記している。

**確認結果**: 時点安全な期待走破タイムモデルは**現時点で存在しない**(`build_baba_bias.py`
はクッション値/含水率という外部センサ値からの帯分けのみで、コース・距離・クラス条件を
制御した回帰モデルではない)。Stage 2で新規構築が必要:

- 提案: 距離・芝ダ・コース区分・馬場状態・クラス名を説明変数とし、`train<=2022`
  (v6と同じ時系列境界)で線形回帰(またはGBM)をfitし、2023-2025全体に対して
  「期待走破タイム」を予測する。2024-2025の結果を見て再fitしない。
- 上がり3F/ペース指数(PCI/RPCI)は定義上すでにレース内相対値(観測分布の外れ具合を
  示す指数)であり、走破タイムほど「距離条件で大きく水準が変わる生の絶対値」ではない。
  したがって上がり3F/ペース信号は簡易的に「レース内偏差値化」だけで時点安全に扱える
  可能性が高く、時計(走破タイム)信号より構築コストが低い。Stage 2ではまずこちらを
  優先して実装し、時計信号の期待値モデルは並行して検証する。
