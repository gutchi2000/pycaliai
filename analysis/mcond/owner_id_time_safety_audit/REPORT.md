## §2 deletion invariance

| ケース | 残した行 | `馬主` | `前走レースID(新)` | `(新/馬番無)` |
|---|---|---|---|---|
| 2024/2025 を削除 → 2023 以前 | 532,525 | 一致 | 一致 | 一致 |
| 2023 以降を削除 → 2022 以前 | 485,252 | 一致 | 一致 | 一致 |

**このテストは PASS するが、馬主については無意味**である。master_v2 は静的な成果物で、
値は export 時点のものをそのまま保持している。上書きは export の**上流（TARGET）**で起きるため、
リポジトリ側で将来行を削除しても値は変わらない。検出には export 時点の違うスナップショット比較（§3）が要る。

**「馬主変更馬だけを抽出」は master 単独では不可能**だった。

| 指標 | 実測 |
|---|---|
| 馬 | 67,973 頭 / 626,774 行（2013-2025） |
| 馬主が生涯で2値以上の馬 | **0 頭（0.000%）** |
| 対照: 調教師コードが2値以上 | 8,011 頭（**11.79%**） |
| 対照: 生産者（本来不変）が2値以上 | 0 頭（0.000%） |
| 複数年に出走した馬 42,470 頭のうち馬主が変化 | **0 頭**（調教師は 7,440 頭） |
| 3年以上にまたがる馬 11,456 頭のうち馬主が変化 | **0 頭**（調教師は 3,498 頭） |

実際には JRA 馬の所有者は取引で変わる（§3 で実測）。それが master に一度も記録されていないこと自体が、
この列が「当時の値」ではない証拠である。

## §3 historical truth との照合

### 3.1 当時の馬主列は手元に無い（ただし TARGET には存在する）

`data/走間分析/*.csv`（TARGET export、2026-06-15）は
**`馬主(最新/仮想)`・`馬主タイプ`・`馬主(レース時)`・`馬主タイプ(レース時)` の4列を持つ**。
つまり TARGET 自身が「最新/仮想」と「レース時」を別概念として区別している。

しかし手元の5ファイルすべてで **`馬主(レース時)` は空（非欠損 0.0%）**。
`馬主(最新/仮想)` は新しい3ファイル（2022年以降のレースを含む）でのみ 100% 埋まっている。
したがって**レース時点の真値との直接照合は、その列を含めた再 export がない限り不可能**である。

### 3.2 代替: export 時点の異なる2スナップショット間の照合

同じ過去レース行を、**cat export（2026-03-01）**と**走間分析 export（2026-06-15）**で突き合わせた。
join key は **`レースID(新/馬番無)` + `血統登録番号`**（馬名 join は不使用）。

| 項目 | 実測 |
|---|---|
| 共通行 | 151,441 行 / 13,680 レース / 19,892 頭 |
| 一致 | 150,940 行（**99.669%**） |
| **不一致** | **501 行 / 491 レース / 68 頭** |
| 馬単位の変化率（106日間） | 0.34% → **年率推定 1.17%** |

年別の不一致（レース年別）:

| レース年 | 共通行 | 不一致 | 率 |
|---|---|---|---|
| 2022 | 30,552 | 29 | 0.09% |
| 2023 | 42,701 | 98 | 0.23% |
| 2024 | 42,234 | 142 | 0.34% |
| 2025 | 35,954 | 232 | 0.65% |

EXP15 の分割で言うと、不一致は selection(2022) に 29 行、development(2023) に 98 行含まれる
（base_train 2016-2021 は走間分析側に値が無く照合できていない）。

不一致の例（同じ過去レース・同じ馬で、export 時点によって馬主名が違う）:

| レース | 血統登録番号 | 2026-03 時点 | 2026-06 時点 |
|---|---|---|---|
| 2025120709050203 | 2023105761 | ケイアイスタリオン | 亀田和弘 |
| 2025113008040804 | 2022101565 | ノースヒルズ | 齋藤慎 |
| 2025112403030603 | 2021104320 | 嶋田賢 | 嶋田一成 |

**解釈**: 過去のレース行の内容が、後から取った export では別の値になる。
これは「その列がレース時点の事実ではなく、export 時点の所有者を過去へ遡って適用している」ことの直接証拠である。

### 3.3 future-owner substitution の件数

- **実測（前向き）**: 上の 68 頭は 2026-03 と 2026-06 の間に所有者が変わった。
  この馬たちの master 行は **582 行 / 568 レース**あり、レース日はすべて変更時点より前である。
  現在の master はこれら全行に「レース後の所有者」を持っており、再 export すればまた別の値になる。
- **後ろ向きの推定**（年率 1.17% が一定と仮定した場合の、レースから export までの経過年数別）:
  1年 1.2% / 3年 3.5% / 5年 5.7% / 10年 11.1%。
  base_train の 2016 年のレースは export まで約10年あるため、**1割前後の行が当時と違う所有者を持つ**と見積もられる。
  これは仮定に基づく推定であり、実測ではない（実測には §3.1 の再 export が必要）。

**読み取り**
1. **どの列を足しても有意な改善は出ない**。全指標で CI95 が 0 をまたぐ。logloss はむしろ悪化方向。
2. EXP15 で観測した R0-prodref − R0-clean の **NDCG@3 +0.0021（5/5 seed）** は、

## §5 判定

**`馬主(最新/仮想)` = future overwrite（leakage）確定**。根拠は4点。

1. master 内で全 67,973 頭が生涯一定。対照の調教師は 11.79% が変化する。
2. export 時点が違うと、同じ過去レース行の値が変わる（501 行 / 68 頭 / 106 日）。
3. TARGET 自身が `馬主(レース時)` を別列として持っている（手元 export では空）。
4. serve では weekly CSV に列が無く、bunseki（**現在**のスナップショット）から馬名 join で復元している。

これに伴う扱い（指示された方針をそのまま適用）:

- **leakage 確定**として記録する。
- **current v6 の過去評価は要再解釈**。v6 は gain 15 位でこの列を使って学習している。
  ただし §4 の通り、切り離したときの測定可能な差は 2023 で有意でない。
  また serve 被覆が 0% のため、**本番の予測時にはこの列の値は届いていない**
  （＝ leakage は主に offline の学習・評価に影響し、同時に train/serve skew を生む）。
- **production model は即変更しない**。
- **time-safe な馬主列は別 artifact として作る**（TARGET で `馬主(レース時)` を含めて再 export する、が唯一の経路）。
- **current-v6 contract には混ぜない**。
- **clean baseline（111列の R0-clean）を正式な科学比較の基準とする**。

## §6 `前走レースID`

| 確認項目 | 実測 | 判定 |
|---|---|---|
| 本当に当該 race 以前の race_id か | 値ありの行で**未来 ID は 0 件**。master 内の同一馬の直前行との一致率 **96.22%**（558,444 行中 537,326）。残り 3.78% の不一致は未検証（dropna で DNF 走が母集団から落ちること、地方・海外戦が master に無いことが候補）。値が入っている行の被覆率は 90.4%（初出走 67,973 行が欠損） | **time-safe** |
| future deletion invariance | 2023 以降削除・2024/2025 削除のいずれでも過去行は不変 | PASS |
| 数値として入れたことで日付 proxy になっていないか | ID 先頭8桁が**前走日付と 100% 一致**。前走日付との相関 0.9999999999986 | **日付 proxy になっている** |
| 同一前走 race の馬を結ぶ情報として働くか | 前走 ID を共有する馬が同居するレースが **36,143 / 41,248（87.6%）** | **働く**（集合モデルでは ID 一致で「前走が同じ」を検出できる） |
| live serve parity | weekly CSV に無く −9999。serve 被覆率 0.0 | **不一致（dead at serve）** |
| 数値精度 | 18桁版の最大 2.025e17 は float64 の正確整数範囲（2^53）を超える。異なる値の数は 18桁版 54,958 < 16桁版 55,024 で、**馬番の情報が丸めで消えている**（実質 16 桁版の重複列） | 要注意 |

**結論**: time-safe ではあるが、(a) 日付 proxy、(b) ID 一致による馬間リンク経路、(c) serve で死んでいる、
(d) 18桁版は精度欠落で重複列、の4点がある。clean contract からの除外は維持する。
ID 生値を vNext に入れるかの判断は、指示どおり別途とする。
