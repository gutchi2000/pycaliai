## 実装バグの発見と修正（透明性のため記録）

**最初の実行では Gate 1 の G1b（短期状態は長期能力より速く動く）が誤って FAIL した。** 原因は評価コード (`run.py` の `gate1()`) 側のバグで、モデル本体 (`latent_state.py`) には問題がなかった。

- `groupby("hid").shift(1)` は「入力フレームの行順」のまま結果を返す。評価コードは `f.sort_values(["hid","date"]).groupby("hid")` でラグを計算していたが、相関に使う `s`・`a` は**ソート前の元の行順**のままだった。ブール選択（`s[ok]`）は両者とも「自分の行順」を保ったまま返るため、`np.corrcoef` が **無関係な行同士をペアにしていた**。
- 修正: `f` 自体を `sort_values(["hid","date"]).reset_index(drop=True)` してから `groupby` するよう変更（1行の書き換え、モデルの定義・ハイパーパラメータ・特徴量には一切触れていない）。
- 修正前後の値: 能力の自己相関 `ac_a` は **−0.006 → 0.976**、状態の自己相関 `ac_s` は 0.0001 → 0.863 に訂正された。修正後は G1b を含む Gate 1 の全8項目が PASS。
- 影響範囲の確認: G1a・G1c〜G1g は単一フレーム内のブール選択のみで計算されており、この並び順バグの影響を受けていなかった（手動再現で確認済み）。
- 特徴量ファイル (`exp03_features.parquet`) やハイパーパラメータ選択・innovation定義の選択はすべて `latent_state.py` の中で一貫した処理で行われており、影響を受けていない。Gate 2 以降の再実行のみが必要だった。

## ハイパーパラメータ（train の着順尤度のみで選択）

**半減期・τa²・qs・βのいずれも格子の端（最大または最小）が選ばれた。** より外側の値が良い可能性はあるが、仕様どおり評価後に格子を広げていない（未解決事項）。
