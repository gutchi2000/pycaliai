# EXP04 データ監査（Gate 0 詳細）

`data_audit.py` の実行結果（`out/data_audit.json`, `out/coverage_by_year.csv`）。

## C1候補（v6の120時点安全特徴）の除外

機械的規則（評価前に固定、結果を見て閾値を変えていない）:
- **R1 恒常欠損**: 2016-2025通算の被覆率 < 5%
- **R2 期間内シフト**: 年別被覆率の最大−最小 > 30pt（収集仕様が期間途中で変わった列）
- **R3 識別子**: 列名に「レースID」「血統登録番号」を含む
- **R4 上書き列**: `馬主(最新/仮想)`（EXP01/EXP02の監査で最新値上書きと確認済み、ここでも同一列として除外）

| 列 | 理由 |
|---|---|
| 前走レースID(新) / 前走レースID(新/馬番無) | R3識別子 |
| 父タイプ名 | R2（年別被覆差0.847）|
| 指定条件 | R2（年別被覆差0.742）|
| 馬主(最新/仮想) | R4 |
| kako5_avg_ninki / kako5_pos_vs_ninki / kako5_upset_good_count | R1（通算被覆0.000＝master上で常時欠損）|
| trnW_5F / trnW_4F / trnW_3F / trnW_Lap1 / trnW_Lap2 / trnW_Lap3 / trnW_days_ago | R2（年別被覆差0.82〜0.97、WC調教データは2021年開始・2022年以降で被覆向上のため2016-2025窓内で収集体制が変わっている）|

**除外15 / 採用105**。`trnH_*`（坂路調教）は2015年開始で評価窓（2016-2025）内では被覆が安定しており除外していない（`out/coverage_by_year.csv`で個別確認可能）。

`kako5_avg_ninki`等3列が通算0%なのは想定外の発見。これらはv6の120特徴に含まれているが、現在のmasterでは実質使われていない（LightGBM側は欠損定数として無視している）。EXP04では候補から機械的に除外する。

## 6〜9月のTARGET入力欠損によって特定環境だけが識別されないか
EXP04は2016-2025の**historical master**データのみを使用し、2026年のserve/TARGET欠損（補正タイムの5/31以降欠損等）は評価対象期間に含まれない。したがってこの懸念は該当しない。

## 期間途中の収集仕様変更を特徴が識別していないか
上記R2規則で機械的に検出・除外済み。個別の年別被覆率は `out/coverage_by_year_detail.csv` に全120特徴ぶん記録。

## オッズ取得時点
`analysis/mcond/market.py` の `pre`スナップショット（確定31〜38分前、既存基盤で確定済み）を再利用。EXP01/EXP02/EXP03と同一定義。

## OOF予測との結合安定性
`data/_research/mcond/base.parquet`（v6スコア・市場確率）と、C1候補特徴（master再読込）・C2/C3候補特徴（既存parquet）を`rid16,ban`で結合する。結合率はGate 0で実測して記録する（`run.py`実行時に`out/gate_results.json`へ記録）。

## 各主環境のレース数
E1（年度）・E2（競馬場）・E3（芝ダ×距離帯）とも、2016-2025のJRA中央競馬データであれば数万〜数千レース規模になることが既知（EXP01-03の年別・EXP02競馬場別集計で確認済み）。最小環境サイズは学習期間（2016-2021）内で1000レース未満なら固定の「other」区分へ統合する規則を`spec.json`に置く（`run.py`実行時に実測し閾値割れがあれば`out/gate_results.json`に記録）。
