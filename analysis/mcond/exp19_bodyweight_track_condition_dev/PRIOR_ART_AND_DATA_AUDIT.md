# EXP19 先行研究・データ監査

## 1. JRA公式馬場データは既に収集済み

### 当日

`fetch_baba_today.py` はJRA公式ページのクッション値、含水率、馬場状態を直接取得する。保存先は `data/baba_today.json`。競馬場ごとに次を保持する。

- クッション値、硬さ区分、測定時刻
- 芝のゴール前・4角含水率
- ダートのゴール前・4角含水率
- 含水率測定時刻
- 取得日時と「当日測定か」の判定

`baba_daily.ps1` は掲載遅延を考慮して再取得する。2026-09-26の実ファイルでは、中山がクッション8.3、芝15.7/16.0%、ダート10.2/10.4%、阪神が8.7、10.9/10.7%、0.6/1.0%で、すべて測定時刻付きだった。

### 歴史

`build_baba_feats.py` はJRA PDFから `data/baba_feats.parquet` を作る。実測は次のとおり。

| 項目 | 実測 |
|---|---:|
| 期間 | 2018-07-27〜2025-12-28 |
| venue-day | 3,164 |
| クッション値充足 | 71.90% |
| 芝GP/4C含水率充足 | 99.84% / 99.84% |
| ダートGP/4C含水率充足 | 99.84% / 99.75% |

クッション値の欠損は主に制度開始前であり、欠損を0にしない。主interaction期間はクッション値が通年存在する2021〜2023とする。

## 2. 公式馬場値の既存検定

`baba_eval.py` は既に以下を試している。

- 競馬場内標準化クッション値・含水率
- 硬い/軟らかい区分
- 馬の過去の軟馬場適性との相互作用
- ダート湿潤×脚質
- 競馬場×surfaceの湿潤時脚質バイアス

`reports/baba_feats_eval.json` の結果は、baseに対して `+baba` が ΔAUC=-0.000304、Δlogloss=+0.000278で悪化した。gain shareは2.80%だったがOOS改善は無い。したがってEXP19で馬場値単独を新仮説として扱わない。track-only armはパイプラインの負対照である。

EXP08は、当日の先行レース結果から逐次推定する潜在的な馬場状態を検定して終了した。これは朝の公式物理値とは入力が違うが、「同日結果から馬場を推定する」仮説は閉じているため再実施しない。

## 3. 当日馬体重

### 歴史源

`data/torch_20130105-20251228.csv` は、今走の `馬体重`、`馬体重増減`、血統登録番号、race ID、馬番、コース条件を持つ。これは `build_dataset.py` が読む `torch_transformer_...csv` とは別ファイルで、現行 `master_v2` には今走馬体重が入っていない。

結果列を使わない構造監査では、2019〜2023のJRA平地に231,068行 / 16,645レースがあり、馬体重200〜800kgの充足は99.807%、血統登録番号欠損は0だった。`馬体重増減`は約10.6%欠損するため、増減欠損を0とみなさず、過去体重から再計算できる場合だけ再計算する。

### forward源

`analysis/bodyweight_forward/collector.py` はJV-Link `0B11`（WH）をT−90〜T−5でappend-only収集する。各snapshotは取得時刻、元CP932 bytesのhash、馬体重、増減、`000`/`999`等のstatusを保持する。2026-09-26に実レースで取得成功済みだが、歴史TARGET値とのparityと発表完了時刻の分布はまだ未検証である。

## 4. 時点の意味

- 公式馬場値は早朝測定で、朝モデルにも利用可能。
- 当日馬体重は発表後のみ利用可能。朝9時の既存v6へ入れると時点違反になる。
- EXP19は馬体重取得後の `late_decision` モデルとして扱う。
- 歴史の `historical_pre_snapshot` は発走約26〜30分前。馬体重がその時点までに揃っていたことをforward実測で確認するまでは、actionableと呼ばない。
- terminal closeは決済価格の情報集合であり、結果情報ではない。締切市場残差が無ければ長期収益の根拠には進めない。

## 5. 使用しないもの

- JRA-VANのTM/DM等の独自指数
- 調教映像、フォーム、併せ馬（現データに存在しない）
- 結果を見て作る体重閾値（±10kg等）
- result-file oddsを判断時点価格とみなすこと
- 馬名join、欠損の0埋め、未来走を含む平均との差
- 今走の着順・タイム・通過順位を特徴へ入れること

## 6. 監査から導く設計

公式馬場値はrace内定数なので、race softmaxでは単独生値が全馬に同じだけ加わり順位に効かない。意味を持つのは馬ごとに変わる量との相互作用だけである。EXP19では、当日体重の馬内偏差と公式物理値の積を主対象にする。

また、馬体重が公開された時点で市場も同じ情報を見る。したがって「モデル単独で成績が上がる」だけでは不十分で、判断時点市場とterminal close市場の両方を基準にする。

## 7. Fableレビューで確定したclean baselineのERRATUM

R0-clean 111列の`斤量体重比`は、masterと歴史torchを1,292行で照合した結果、`斤量 / 今走馬体重 × 100`の小数1桁丸めと100%一致した。前走馬体重由来ではない。したがって学習側のR0-clean/v6は今走馬体重を間接的に持つ一方、serveでは当日馬体重不在時に定数化するtrain/serve skewがある。

EXP19の主nullは`斤量体重比`を除いた110列`R0-clean-nobw`とし、rolling OOFを新規構築する。`前走馬体重`、`前走馬体重増減`、`斤量`、`馬齢斤量差`は残す。本番v6の修正は本実験の範囲外である。EXP15/16A/17の結論は、baselineを強くする側の混入なので方向を覆すものとは扱わないが、数値再現時は契約差を明示する。

## 8. v0.2-frozen

Fable最終レビューの必須修正により、WP #5はW主blockに存在する`bw_robust_z5`と`moisture_gradient_z`の積へ変更した。`bw_change_pct`は説明用のままで、主modelにもWPにも入らない。これによりA2がWへ入れなかった体重変化率の主効果を回収する経路を閉じた。
