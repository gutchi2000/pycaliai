## 1. `diag_upset_decomposition.py` / `diag_flop_detector.py`（最も近い先行研究）

`analysis/diag_upset_decomposition.py`（OOS 2024-25、6,878レース、既に実行済み・
`reports/_diag_upset_oos.parquet`に保存済み）が、v6を「予測問題」「期待値問題」
「組み合わせ問題」に分解する目的で以下を計算していた（全文読了済み、コード引用）:

- **ラベル**: `hon_top3 = int(hon in {wi, pi_, si})`（◎=最高スコア馬が勝馬/複勝馬/
  ショー馬のいずれかに入るか、二値）。`hon_win`（◎単勝的中）も別途。
- **特徴**: `s1,s2,s6`（スコア上位3頭の生スコア）、`gap_12,gap_16`（差）、`entropy`
  （PL確率のシャノンエントロピー）、`score_std`、`p1_max`（◎の較正前確率）、
  `baba`（馬場状態）、`dist`（距離）。
- **分割**: train=2024 / test=2025（`diag_flop_detector.py`側、honest OOS）。
  `diag_upset_decomposition.py`自体は2024-25合算でOOS集計（学習には使わない、
  記述統計のみ）。

`diag_flop_detector.py`（111行、全文読了済み）はこのparquetを読み、
`flop = 1 - hon_top3`（◎が複勝圏外に飛んだか）を目的変数として:

- **Q9**: train=2024で決めた`entropy`/`gap_12`の分位ゲートをtest=2025へ固定適用
  （honest OOS）。残存率・◎複勝圏率・単複/馬連ROIを報告。
- **Q10**: `entropy`,`gap_12`,`n`,`baba_n`の単変量ROC-AUC、および4特徴ロジスティック
  回帰でROC-AUC/PR-AUC、上位10/20/30/40%のrecall/precision。
- **Q11**: `score_std`追加＋LightGBM（200推定器、15リーフ）で同様。feature importance
  報告。
- **Q12**: LightGBMのflop確率で上位X%（0/10/20/30/40%）を除外し、残存レースの
  ROIを券種別に集計。

**既存メモリ（[[project_loss_is_anchor_prediction]]）に記録された結論**:
検知力の天井は **ROC-AUC≈0.65 / PR-AUC≈0.51**（entropy主導、gap/頭数は弱く、
馬場はほぼ無力0.506）。低entropy×高gapゲートで◎複勝率61%→75-79%まで上げても
**ROIは92%止まり（控除率未満）**。flop確率上位10%除外で+1-2pt、それ以上の除外は
フラット（長期馬の代償払戻を失うため）。**総括: 検知は本物だが市場priced＝
収益化せず**。

## 2. 項目5への回答: 「v6の高確率馬だけを対象とした過去分析」は存在する

`diag_upset_decomposition.py`のQ1〜Q3・Q5/Q6・Q8は全て、◎（=v6が最高スコアを
付けた馬）を軸にした分解であり、暗黙にv6の"高確率馬"（正確には"最高スコア馬"、
必ずしも確率が高いとは限らないが実務上ほぼ同義）に限定した分析である。
Q3では「◎複勝圏内レース限定」のROIも別途集計済み。**EXP10がゼロから着手する
領域ではなく、既存の分解に対する「未検証の追加軸」を探す位置づけになる**。

## 3. EXP10の候補ターゲットと既存研究の重複度（項目4対応）

ユーザー指定の6候補それぞれについて、上記先行研究がカバーする範囲を判定する:

| EXP10候補ターゲット | 既存研究での扱い | 重複度 |
|---|---|---|
| DNF/非完走（中止・除外・失格） | **扱いなし**。`hon_top3`/`flop`は着順ベースの二値で、中止・除外・失格は`convert_finish()`で除外済みの母集団（DATA_AUDIT.md §1参照）なので、既存分析の対象レースにそもそも含まれていない | **重複なし（未踏査）** |
| 人気・AI期待に対する大幅な下振れ（着順の相対値） | `hon_top3`(二値: 複勝圏内/外)は粗い近似。連続的な「どれだけ下振れたか」（人気との乖離幅、AI期待順位との乖離幅）は未測定 | **部分重複（粒度が違う）** |
| 低い着順（絶対値） | 直接には未集計（`hon_top3`は複勝圏の有無のみ、4着以下の中でどれだけ悪いかは見ていない） | **部分重複** |
| 走破タイム残差の極端な悪化 | 未着手。`diag_upset_decomposition.py`は距離(`dist`)は見るがタイム残差は特徴に含まない | **重複なし** |
| 上位3着内確率が高い馬の複勝圏外 | **`flop`ラベルそのもの**。ただしcontrol変数がentropy/gap_12/gap_16/n/baba/score_stdに限定され、**市場確率・人気順位・出走回数・休養日数は含まれない**（EXP10主仮説の必須統制変数） | **強い重複、ただし統制変数が不足** |
| 1番人気・AI◎の大敗特化 | ◎軸（=AI視点）の分析はあるが、**1番人気(市場視点)軸の同種分析は未着手**。「大敗」の定義も`flop`（複勝圏外の二値）どまりで、着差の大きさは未測定 | **AI◎側のみ部分重複、市場人気側は重複なし** |

**結論**: 「AI◎が複勝圏外に飛ぶか」という二値予測は既に検定済み・天井確定・
市場priced判定済み（再走禁止範囲）。EXP10がこれと同じ土俵で再走する価値がある
唯一のケースは、**ユーザーが明示的に要求した追加統制変数（市場確率・人気順位・
出走回数・休養日数）を入れた上でのfull-control再検定**であり、これは
「同一仮説の4回目の言い換え」ではなく「未統制だった交絡変数を塞ぐ」という
正当な理由がある（[[project_dr01a_erratum_policy]]の「同一仮説の繰り返し」判定
基準に照らし、統制変数の追加は新規性として認められる）。それ以外の5候補
（DNF・相対下振れ連続値・絶対着順・タイム残差・1番人気軸）は**真に未踏査**。

## 4. `project_trouble_proxy_priced`（既存のトラブル代理特徴、priced判定済み）

`kako5_hidden_good_count`（`parse_kako5.py:173-180`、過去5走で「着順>5 かつ
上がり3F<34.5」＝展開不利があったにも関わらず地力はあった、を示す代理特徴）は
次走の単勝/複勝ROI差を検定し**有意なし**（単勝+4.7pt CI[-5.6,+15.4] p=0.80、
複勝+0.3pt CI[-3.8,+4.7]）。**公開列由来のproxy特徴は市場が既に織り込み済み**、
という原則が確立している。ただし、この特徴は「過去の不利」を**予測特徴**として
使う話であり、EXP10の主眼（「今回のレースで大敗するかを検知するラベルを作れるか」
という**ラベル設計**の話）とは層が異なる。関連はするが直接の先行研究ではない。

## 5. EXP02（項目6、出走回数・休養日数の重複）

`project_mcond_exp02_dynamic_skill`（動的対戦能力、Weng-Lin PL）の探索分解で
確立した事実（2026-09-18）: **動的能力の効果の約3/4は出走回数・休養日数という
生の事実に由来し、モデル自身のσ（不確実性）の固有寄与はゼロ**。この2変数は
ELO/Glickoを制御した後も有意に残る（主判定の約1/4）。

**EXP10への含意**: ユーザーが主仮説の統制変数リストに出走回数・休養日数を
明示的に含めたことは、EXP02の実測結果と整合的であり正当化される
（この2変数を欠いた統制は「見せかけの下方リスク検知」を生みやすいという
実証済みの懸念）。EXP10で新規に「休養明け・出走過多」という切り口を主軸には
できない（EXP01/EXP02で既に間隔・出走回数の主効果は検定済み、市場は
ほぼ織り込み済みで利益化せず）が、**統制変数としての採用は必須**とする
ユーザー指示は先行研究と整合する。

## まとめ（Stage 0 先行研究監査の結論）

1. 「AI◎の複勝圏外」という一次元だけは既に検定済み・天井確定（AUC≈0.65）・
   市場priced。再走するなら統制変数の拡張という限定的な正当化のみで許容。
2. DNF・相対下振れの連続値・絶対着順・タイム残差・1番人気軸の5候補は
   **真に未踏査**。
3. 出走回数・休養日数を統制に含める判断はEXP02の実測と整合的。
4. 「負けた馬=陽性」という禁止された設計と、既存の`flop`（複勝圏外）ラベルは
   別物であることに注意（`flop`は「AIの期待(◎指定)」との相対で定義されており、
   単なる敗北ではない。EXP10の新ターゲットも同じ原則＝**相対的な期待との乖離**
   で定義する必要がある、そうしないとv6の逆モデルになるという禁止条件に抵触する）。
