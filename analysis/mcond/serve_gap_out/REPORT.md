# offline と本番の ◎勝率差の分解 (2026-09-18)

`analysis/mcond/serve_gap_diagnosis.py`。本番処理は変更していない（旧モデルは一時的な別名で置き、終了後に削除）。

## 物差し
「◎の勝率 − 同じレースの**確定オッズ1番人気**の勝率」。
期間・レース構成で難しさが変わっても市場も同じだけ変わるので相殺される。全期間で同じ形式のオッズが取れるのは確定オッズだけなので、これに統一した。
※ 9/17〜18 に報告した「約 −7.5pt」は bundle 内の朝のオッズ基準で、物差しが違う。確定オッズの1番人気は朝の1番人気より当たるので、差の絶対値は大きく出る。

◎の定義: bundle は `ai_rank==1`（生スコア最大）。本番 bundle の `p_win`（isotonic 較正後）は **18.1% のレースで1位と2位が同値**に潰れているので使わない。

## 分解（配信済み −12.29pt → offline −3.85pt、差 8.4pt）

| 要因 | 大きさ | 根拠 |
|---|---|---|
| 対象レース集合の違い | **0.2pt** | O −4.03 → Ow −3.85 |
| 学習版・モデル版の違い（旧v6 → C1） | **0.15pt（なし）** | P −9.03 → R −8.88、同一レース・同一コード |
| serve 時の特徴生成・入力データの違い（配信当時のコード → 今のコード） | **3.3pt** | S −12.29 → P −9.03、同一レース・同一モデル。補正タイムの off-by-one 修正などを含む |
| 較正処理 | 評価に影響なし | ◎は生スコアで判定。ただし本番の `p_win` を使う下流（買い目）は18%のレースで同値の影響を受け得る（本診断の範囲外） |
| 残り（期間の違い ＋ 2026年の serve 特徴と offline 特徴の違い） | **5.0pt** | R −8.88 vs Ow −3.85。2026年には offline と同じ特徴を作れる master が無いため、同一レースでこの2つは分離できない |
| うち、入力特徴の欠損（TARGET 補正タイム 5/31 途切れ）の可能性 | 4-5月と6-9月で **4.7pt の差** | R 4-5月 −5.78 vs 6-9月 −10.52（同じコード・同じモデル）。季節差と区別できず、CI も広い |

## 「serve損失」と呼べるか

仕様 §4 の基準（条件を一致させても残る差だけを serve 損失と呼ぶ）に従うと:

- **入力がそろっている 4〜5月では、今のコードの本番印（−5.78, CI [−10.3, −1.1]）と offline（−3.85）の差 1.9pt は CI の範囲内**。この期間については serve 損失を主張できない
- 6〜9月の約6.7pt の差は、入力特徴（補正タイム等）の欠損と期間差が重なったもので、条件が一致していない。これを「serve 損失」とは呼ばない。**入力特徴の欠損**として扱う
- 配信済みの印と今のコードの差 3.3pt は、既に修正されたコード・入力データの問題（過去の配信の損失）

**約6pt（本物差では 8.4pt）を、研究成果に必要な改善量と混同しないこと**: そのうち 3.3pt は既に修正済み、0.2pt はレース構成、残りは主に 6月以降の入力欠損と期間差で、同一条件の serve 損失としては確認できていない。
