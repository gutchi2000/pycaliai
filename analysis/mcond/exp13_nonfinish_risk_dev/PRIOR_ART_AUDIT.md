# EXP13 Stage 0 — 先行研究監査（出走後の中止・非完走リスク）

**作成日**: 2026-09-22　**状態**: Stage 0 監査のみ。実装・学習・バックテスト・
2024/2025年性能開封・ROI評価は一切行っていない。

**対象**: 「馬券購入後、競走を開始した馬が正常に完走しないリスク」
（`started_but_did_not_finish`）。取消・競走除外・発走除外・出走取消・返還対象
（＝競走開始前に確定する事象）は主目的変数から明確に分離する（詳細は
`LABEL_CODEBOOK.md`）。

**結論**: 本テーマ（出走後非完走のリスク予測）を直接対象にした過去研究は
**存在しない**。関連する実装は以下の2種類に限定される:
1. EXP10（完走馬限定のcatastrophic downside、母集団が異なる。§3で詳述）
2. 決済層（`canonical_settlement.py`, `generate_results.py`等）でのDNF/返還の
   区別（予測ではなく「結果が確定した後の払戻計算」用途）

## 2. 決済層における既存のDNF/返還区別（再利用可能な参照実装）

`tests/test_canonical_settlement.py`・`analysis/evaluate_wide_residual_forward.py`
から、本番の決済ロジックは既に「DNF＝賭け金没収（負け扱い）」と「返還対象
（取消・除外）＝払戻あり」を区別して実装済みであることを確認した。これは
EXP13が新規に発明する概念ではなく、**本番運用で既に確立された区別と整合する
設計**であることの裏付けになる（`LABEL_CODEBOOK.md`の主張と決済層の実装が
一致することを確認済み）。

- `normalize_result(rows, non_refunded_zero_horses={...})`: 指定した馬番を
  「返還されない0件」＝DNF馬として明示的に扱い、通常の敗北と同じ決済（負け）
  にする。
- `evaluate_wide_residual_forward.py`のコメント「通常のexportは返還とDNFを
  区別できない」は、**通常のTARGET出走表export（週次CSV等）だけでは判別
  不可能**という制約の存在を示す一次証拠であり、EXP13が生kekkaデータ
  （`着順`列の`止`/`外`/`消`コード）を使う必要がある理由と直結する
  （`DATA_AUDIT.md`§1参照）。

## 3. EXP10との違い（ユーザー指定、必須記載事項）

| | EXP10（大敗・中止・能力未発揮リスク） | EXP13（出走後の中止・非完走リスク） |
|---|---|---|
| 対象母集団 | **完走馬のみ**（`着順`が数値の行、master_v2がそのまま使える） | **出走馬全体**（完走・中止を含む。除外・取消は母集団に含めない） |
| 目的変数の性質 | 正常完走した馬の中での相対的な下振れ（人気・AI期待との乖離） | 出走した馬が完走できたか／できなかったかの二値 |
| データソース | master_v2で完結（追加のraw結合は特徴構築のみ） | **master_v2は非完走行を`dropna`で除去済みのため使用不可**。生kekka/add_ファイルからの母集団再構築が必須（`DATA_AUDIT.md`§1・§4） |
| Stage1結論 | **完全終了**。既存の時点安全な表特徴＋完走馬限定headはB3を上回らず（`RESEARCH_STOPLINE_20260921.md`§2参照） | 未着手（本Stage0がキックオフ） |
| RESEARCH_STOPLINE上の位置づけ | §2「失敗した正確な仮説」に記載済み | §3「未検証として残る範囲」の**EXP10由来項目1**「DNF・中止・取消・除外の別母集団（完走馬限定の各実験のスコープ外）」に該当。EXP10終了時に明示的に「未検証・別仮説として保留」と記録された対象そのもの |

**EXP10自身のPRIOR_ART_AUDIT.md（2026-09-21付）の記述を直接引用**:
> 「DNF/非完走（中止・除外・失格） | 既存分析の対象レースにそもそも
> 含まれていない | **重複なし（未踏査）**」

すなわちEXP10自身が、DNFはEXP10のスコープ外であり未踏査であることを
Stage 0の時点で明記していた。EXP13はこの明示的な空白を埋める、EXP10とは
**独立した母集団**を対象にする新規実験であり、EXP10の蒸し返しではない。

## 4. EXP02（出走回数・休養日数）との関係

EXP10のPRIOR_ART_AUDIT.mdが確立した事実を継承する: 動的能力の効果の約3/4は
出走回数・休養日数という生の事実に由来する（`project_mcond_exp02_dynamic_skill`）。
EXP13のユーザー指定候補特徴にも「career starts」「days since last race」
「連闘・短期出走」「長期休養」が含まれており、これはEXP02の実測結果と整合的
（休養パターンが非完走リスクの統制変数として必須という位置づけは、EXP10と
同じ理由で正当化される）。

## 5. その他の関連死亡ルート（EXP13の解釈に影響しうるもの）

- `project_trouble_proxy_priced`: 過去の不利（展開不利等）を**予測特徴**として
  使う場合、公開情報由来のproxy特徴は市場に織り込み済みという既知の結論
  （`kako5_hidden_good_count`のROI検定、有意なし）。EXP13が「過去の非完走
  回数」等を**予測特徴**として使う場合も同じ壁に当たる可能性を主要な帰無
  仮説として想定すべき。ただしEXP13の主目的は「予測特徴の有効性」ではなく
  「**ラベル自体の構造**（started_but_did_not_finishが構築可能か）」である点で
  EXP10と同じ注意が必要。
- `project_longshot_weakness`: 真の穴馬（15倍以上）でAIの精度が構造的に
  低下する。非完走イベントが人気薄に偏在する場合、同じ天井に当たりうる
  （Stage1で母集団の人気帯分布を確認すること）。
- `project_jravan_guideline_compliance`: 馬体重（今走）の扱いに関するガイドライン
  制約。EXP13が候補特徴に挙げる「馬体重」「馬体重変化」に直接関わる
  （`DATA_AUDIT.md`§5で詳述）。

## まとめ

1. 「出走後に完走しない馬」を予測対象とした研究はリポジトリ内に**存在しない**
   （真に未踏査）。
2. 最も近い先行研究（EXP10）は明示的にこの母集団を対象外としており、
   EXP10自身がそのことをStage 0で記録済み。EXP13はEXP10の蒸し返しではない。
3. データ処理層（決済ロジック）では「DNF≠返還対象」という区別が既に実装
   されており、EXP13のラベル設計はこの既存区別と整合する。
4. EXP02の実測（出走回数・休養日数の重要性）はEXP13の統制変数選定を
   裏付ける。
5. 予測特徴としての「過去の不利」proxy一般に対する市場priced懸念は、EXP13の
   候補特徴（過去の非完走回数等）にも同様に適用されうる帰無仮説として
   意識する。
