## 1. master_v2は非完走行をdropしている（項目4、確認）

`build_dataset.py`の該当箇所を実際のコードで確認した（EXP10 DATA_AUDIT.md
§7の確認を本セッションでも再確認、行番号一致）:

```python
# build_dataset.py:75-84
def convert_finish(series):
    zen2han = str.maketrans("０１２３４５６７８９", "0123456789")
    converted = series.astype(str).str.translate(zen2han)
    return pd.to_numeric(converted, errors="coerce")   # 止/外/消/丸数字は全てNaN

# build_dataset.py:321
master = master.dropna(subset=["着順"])   # NaN行(=非数値着順)を完全削除
```

実データで直接検証: `data/master_v2_20130105-20251228.csv`（626,774行）の
`着順`列は**非数値・欠損ゼロ、値域1〜18で全て`出走頭数`以下**（本セッションで
実測、`pd.read_csv`+`value_counts`で非数値行0件を確認）。**`止`/`外`/`消`/
丸数字の行はmaster_v2に一切存在しない**ことを再確認した。

さらに、`master_v2`の`芝・ダ`列は「芝」「ダート」の2値のみで**障害レースの
行が1件も存在しない**（本セッションで実測、value_counts）。つまりv6モデルは
**障害レースを一度も学習・スコアリングしたことがない**。これはEXP13の障害
サブ母集団に重要な含意を持つ（§3で詳述）。

## 2. 非完走馬への時点安全な特徴再構築（項目4）

### 2.1 予測時点特徴の再構築可否

`止`（中止）行は出走が確定していた馬であり、`LABEL_CODEBOOK.md`§1の通り
今走の記述列（`頭数`・`芝・ダ`・`クラス名`・`距離`等の出走表相当情報）は
外部kekkaファイルに完全に保持されている。これらの馬の**過去走履歴に基づく
特徴**（`kako5_*`・`course_n_prev`・`jockey_win_rate`等、`master_v2`の
120特徴の大半）は、馬個体の識別子（血統登録番号または馬名）とレース日付が
あれば、`build_dataset.py`の既存JOIN群と原理的に同じロジックで再構築できる
——これらの特徴は「その馬が過去にどう走ったか」に基づくものであり、**今走
自体が完走したかどうかには依存しない**構造だからである。

**ただし現状のパイプラインはこの再構築パスを持たない**。`build_dataset.py`は
最終的に`dropna(subset=["着順"])`で非完走行を除去する設計のため、非完走馬の
行に対して同じ特徴構築ロジックを最後まで通す経路が存在しない。Stage1で
新規に構築が必要（既存JOINロジックの再利用は可能、母集団の起点だけを
「完走した行」から「出走した行（`止`含む）」に差し替える改修が必要）。

### 2.2 v6モデルへの同一120特徴入力（学習エンコーダでの安全な変換）

`unified_rank_v6.pkl`のfeature_colsとencodersは`build_dataset.py`が生成する
特徴と同一スキーマを前提にしている。§2.1の再構築ができれば、**同じ
encoder（`joblib.load`されたカテゴリカル変換器）で変換すること自体は技術的に
可能**（encoderは学習時に固定されており、新しい行を既存カテゴリ空間へ
写像するだけの操作）。未知カテゴリの扱いは既存の`frozen_encode.py`
（EXP05-Fが同種の用途で使用中、未知カテゴリ→0ベクトル）と同じ方式を流用できる。

### 2.3 非完走馬だけ特徴欠損率が高くないか

**未検証**（Stage1で個別確認が必要）。理論上、`止`となった馬が「休養明け」
「長距離初挑戦」等の特殊な出走歴を持つ場合、`kako5_*`系の過去走ベース特徴の
カバレッジが通常より低い可能性がある（例: 新馬でのdébut後即中止等）。§1の
実測で新馬（デビュー戦）の陽性率がやや高い（0.421% vs 0.340%）ことは、
この懸念と整合する弱いシグナルだが、確証には至らない。

### 2.4 OOS raw scoreを2015〜2025年で作れるか

技術的には可能（§2.1・§2.2の再構築パスが完成すれば、v6モデル自体への
入力は通常のスコアリングと同じ）。ただし**「同じデータで学習された
v6モデルを使う」ことと「時点安全性」は別問題**であることに注意する
必要がある: v6は2013-2022年をtrain、2023年をvalidで学習しているため
（CLAUDE.md記載の時系列分割）、2023年以降のOOS評価は既存の分割規律
（develop=2023固定→2024/2025は本Stage0を含め未開封のまま）と整合させる
必要がある。

### 2.5 市場確率を判断時点で取得できるか

**可能、確認済み**。`LABEL_CODEBOOK.md`§1の通り`止`行は100%単勝オッズを
保持している（市場が値付けしていた＝発走前の市場確率が取得可能）。
複勝・馬連等の同時点オッズは外部kekkaファイルには含まれないため、
単勝de-vig確率のみが判断時点特徴として直ちに使える（EXP05-Fと同じ
de-vig正規化ロジックを流用可能）。

### 2.6 ★非完走行を追加するとレース内softmaxの分母が変わる（最重要、ユーザー指摘の核心）

`export_marks_json.py`の実装を確認した:

```python
# export_marks_json.py:239-240
w = PL.pl_weights(scores)       # scores = g_orig（そのレースの全行）のモデルスコア配列
p_win_vec = PL.all_tansho(w)    # Plackett-Luceでレース内softmax正規化
```

`p_win`（および複勝・馬連等の派生確率）は**そのレースに渡された行の集合
（`g_orig`）全体でPlackett-Luce正規化される**。現状の`g_orig`は
`master_v2`（非完走馬dropna済み）由来のため、**既存の履歴的p_win/PL確率は
非完走馬を除いた（頭数が実際より少ない）分母で計算されている**。

これはEXP13にとって二重の意味を持つ:
1. **EXP13が新たに構築する非完走馬入りの母集団に対しては、既存の
   保存済みp_win/PL確率を後から結合してはならない**（分母が異なるため、
   完走馬側の確率も含めて全て歪む）。ユーザー指示通り、**出走時点の全出走馬
   （`止`を含む、`外`・`消`を除く）を母集団としてPL確率を再計算する必要が
   ある**。
2. 逆に、**現在本番で運用中のv6の`p_win`自体（`外`・`消`を除いた出走確定
   馬全体で計算）は、正しい設計である**——`外`・`消`は発走前に確定するため、
   実際の出走馬だけで正規化するのが実務上も正しい（本番の`export_weekly_marks.py`
   は当日出走表＝出走確定後の馬だけを処理しており、この点は問題ない）。
   問題が起きるのは**過去データを使ってOOS評価用のPL確率を再構築する場面
   （§2.4）に限られる**。

**結論**: EXP13のStage1で非完走馬入りのOOS評価をする場合、母集団を
「`止`+数値着順+丸数字（＝`started`=1の全馬）」で確定した上で、**その
母集団全体に対してPL正規化をゼロから再実行する**専用パスが必須。既存の
`export_marks_json.py`のロジック自体（`PL.pl_weights`→`PL.all_tansho`）は
再利用できるが、**入力する`g_orig`の構築元をmaster_v2から§2.1の再構築パスへ
差し替える**必要がある。

## 3. 障害レースにおけるv6の不在（新規発見、項目4関連）

§1の通りv6は障害レースを学習・スコアリングしたことがない。これは
`LABEL_CODEBOOK.md`§3の実測（障害の陽性率5.26%、平地の14-17倍）と合わせ、
**障害サブ母集団に対してはS1以降の「v6確率」を含む比較モデル群
（`MINIMAL_FALSIFICATION_PLAN.md`のS1-S4）がそのままでは適用できない**
ことを意味する。障害を分析する場合は以下のいずれかが必要:
- v6確率を使わないS0のみの縮小比較（頭数・距離・馬場等の構造的特徴のみ）
- 障害専用の別モデルを新規学習（Stage1のスコープを大きく超える）

Stage1では障害を「構造的な記述統計のみ」の扱いとし、S1以降の比較モデル
群は平地（芝・ダート）限定とすることを推奨する。

## 4. 疾病・故障の構造化データ（EXP10 DATA_AUDIT.md§3を再確認、変更なし）

**存在しないことを再確認した**（EXP10の結論をそのまま継承）:
- `jvlink_changes.py`のAV/JC/TC/WHフィードは当日限定のライブ機能で、
  理由コードを保持せず、過去のアーカイブとしても機能しない。
- リポジトリ全体の`疾病|故障|骨折|外傷|屈腱|事故`検索でも構造化データは
  ヒットしなかった（`PRIOR_ART_AUDIT.md`§1参照）。

**結論**: `LABEL_CODEBOOK.md`の通り、EXP13は「非完走リスク」の二値のみを
扱い、理由別分析はスコープ外。

## まとめ（Stage0必須報告項目）

- **v6スコア再生成の可否**: 技術的に可能（§2.1-2.2）だが、既存パイプラインに
  非完走馬向けの再構築パスが存在せず、Stage1での新規実装が必要。
- **市場確率の可否**: 可能・確認済み（§2.5）。
- **特徴の時点安全性**: 候補特徴の大半は既存列または既存列からの導出で
  時点安全に構築可能（§5表）。馬体重（今走）のみ構造的に利用不可。
- **欠損・選択バイアス**: master_v2のdropna設計により、非完走馬は現行の
  v6学習・評価母集団の外側に完全に存在する（選択バイアスが構造的）。
  障害レースはv6が一度もスコアリングしたことがない別カテゴリ（§3、新規発見）。
- **PLソフトマックスの分母問題**（§2.6）: 既存のp_win/PL確率を後から結合
  してはならない、出走時点の全出走馬を含めて再計算する必要がある、という
  ユーザー指摘を実装の一次証拠（`export_marks_json.py`）で確認した。
