## 2. 過去走で同走した全馬を時点安全に連結できるか（項目2）

**可能、実装・実データ検証済み**。`o1_opponent_quality_check.py`で以下を
実装:
1. `前走レースID(新/馬番無)`（master_v2既存列）で自己結合し、対象馬の
   前走の(レースID, 血統登録番号)キーから、そのレースの同一レースID内・
   他馬を`groupby(レースID)`で取得。
2. 対象馬自身を除いた他馬のv6スコア平均を計算（レース平均×n-自分のスコア)
   /(n-1)、O(1)で計算可能）。
3. 2023年development・530,165/626,774行（84.6%）で`opponent_avg_quality_prev`
   が構築可能だった（残りはデビュー戦等、前走が存在しない行）。

**既知の落とし穴（EXP01で先行確認済み）**: `前走レースID`が指す行が
必ずしも真の「直前のレース」とは限らない——地方・海外・障害を挟んだ
場合、masterの直前行が真の前走でないケースがあるため、EXP01
（`analysis/mcond/exp01_choice_dev/build_features.py:7-9`）は`前走日付`列との
一致チェックで無効化する設計を採用している。**EXP12がグラフを構築する際、
同じ検証（前走日付との整合性チェック）を必ず踏襲する必要がある**
（本Stage0では簡易版のみ実装、Stage1で厳密化要）。

## 3. 馬―レース二部グラフを対象日以前だけで構築できるか（項目3）

**可能**。master_v2は`血統登録番号`（馬ノード）と`レースID(新/馬番無)`
（レースノード）の対応が明示的にあり、任意の時点$t$について
`日付 < t`でフィルタするだけで、その時点までの二部グラフ（馬-レースの
接続）を構築できる。本Stage0では**1-hop（直前のレースのみ）**を実装した
（項目2参照）が、真の多段グラフ（馬の全過去レース）は`血統登録番号`で
groupbyし、各行の前に来る全レースを辿ることで拡張できる（実装コストは
中程度、O(n)で全馬の全履歴をソート・走査すれば良い、EXP10/EXP11で確立
した「日付ソート+累積辞書」パターンを流用可能）。

**JRA限定という制約**: master_v2は構造的にJRA10場のみ（項目4参照、
DATA_AUDIT.md本体では省略、PRIOR_ART_AUDIT.md §4に詳細）。グラフの
エッジは必然的にJRA内の対戦に限定される。

## 8. 2023年だけで方式を固定し2024・2025年で評価できるか（項目8）

構造的には問題ない。EXP07-11で確立した「develop=2023固定→2024/2025
frozen評価」パターンをそのまま踏襲できる。グラフ構築のハイパーパラメータ
（ホップ数、減衰率、embedding次元数等）は2023年developmentのみで選択し、
2024・2025年へ固定適用する設計とする。

**ただしグラフ特有の追加考慮点**: 多段伝播（2-hop以降）を使う場合、
「対象馬の対戦相手の対戦相手」の情報が、対象馬自身の過去だけでなく、
**対戦相手側の未来レース**（対象日より後）を含んでいないか、という
時点安全性の検証がEXP10/EXP11以上に複雑になる。例えば「この馬が負かした
相手が、後にG1で好走した」という情報を使う場合、その相手の「後の
G1好走」が対象レースの時点で既に発生済みかどうかを厳密にas-of化する
必要がある。この検証は本Stage0では未実施（Stage1で必須の設計項目とする）。

## 比較順序（O0-O6、ユーザー指定・凍結）

| モデル | 内容 | Stage0時点の位置づけ |
|---|---|---|
| O0 | v6+市場 | 既存、EXP06-11で確立したbaseline |
| O1 | 単純な過去対戦相手平均 | **本Stage0で一次診断実施済み**（§7参照、小さいが非ゼロ） |
| O2 | 既存ELO/Glicko/EXP02 | **全て死亡確定済み**（PRIOR_ART_AUDIT §1.1-1.2、EXP02は別仮説で別軸）。素朴な再検定はしない |
| O3 | 1-hopネットワーク特徴（個体識別ベース、時点安全に再構築） | Stage1の最有力候補 |
| O4 | 2-hop/PageRank等 | O3がfull-control gateを通過した場合のみ検討 |
| O5 | graph embedding | O4通過後のみ検討 |
| O6 | GNN | O5通過後のみ検討、最終手段 |

**方針（ユーザー指示に基づく）**: 高度なモデルを作ること自体を目的とせず、
各段階でfull-control gateを通過した場合のみ次段階へ進む。O1の効果量が
小さいことを踏まえ、O2の素朴な再検定はスキップし、O3（個体識別ベースの
1-hop、EXP01の前走日付検証を踏襲した厳密なas-of実装）から着手する。
