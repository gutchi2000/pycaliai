## 5. モデル

| 記号 | 構成 | 役割 |
|---|---|---|
| **R0** | v6 レシピ: LightGBM `lambdarank`、truncation 5、ラベル clip(6−着順)、v6 の Optuna ハイパラ（凍結）、木の本数は inner の NDCG@5 で決める、カテゴリは LabelEncoder の整数を数値として使う、欠損は −9999 | 基準 |
| R0-ref | R0 と同じだが120特徴（本番互換） | 参考値。Gate には使わない |
| R0-τrace | R0 のスコアに、レースごとの温度 log τ_r = a + b·log n_r + c·maxprob_r + d·H_r を inner ブロックで fit | G7 の基準（レース確信度だけの補正） |
| **R1-noctx** | R1 から文脈経路を外したもの（文脈の入力を学習済み定数に置き換える）。パラメータ数は R1 の ±5% に合わせる。損失・カテゴリ処理・学習手順は R1 と同一 | 文脈効果を切り出すための双子 |
| R1-noctx-2x | R1-noctx のパラメータ数を約2倍にしたもの | 容量の統制（G6） |
| **R1** | DeepSets（下記） | 検定対象 |

**R1 の構造（凍結案）**
- 馬ごとのエンコーダ: h_i = φ(x_i)
  - φ: 入力 → 256 → 128、LayerNorm + GELU、dropout 0.1
- マスク付きのプール（有効な馬だけ）
  - 自分を除いた平均: m_{−i} = (Σ_j h_j − h_i)/(n−1)
  - 最大値: M = max_j h_j
  - 出走頭数: log n
- 文脈: c_i = [m_{−i}, M, log n]
- 出力: s_i = ρ([h_i, c_i, h_i − m_{−i}])
  - ρ: → 128 → 64 → 1
- 構造全体が permutation-equivariant で、各馬のスコアを出す。
- **BatchNorm は使わない**。学習バッチ内の他レースと統計が混ざるため。

**学習設定（全 NN で共通）**
- AdamW、lr 1e-3、weight decay 1e-4、1バッチ = 256 レース、最大 40 epoch、patience 4。
  early stopping は inner ブロックの race-level win logloss で行う。
- 数値特徴: 学習行の中央値で補完し、欠損フラグを付ける。学習行の分位点で robust scaling する。
- カテゴリ特徴（主案 C2）: 学習埋め込み。
  - 次元 = min(16, ⌈1.6·K^0.56⌉)（K = カテゴリ数）
  - 学習行で20件未満の値は rare バケツにまとめ、未知の値は unk にする。

**R1 と R1-noctx の損失【既定案、§11 R-2】**
- 段階ラベル rel に対する馬ごとの MSE（race 重み付き）。レース内で結合しない pointwise 損失。
- 勝率は全モデル共通で p_win = softmax(s/τ_k) とし、τ_k は inner ブロックで
  1着の条件付きロジット最尤で推定する（`analysis/mcond/v6base.fit_tau` と同じ方式）。

**R2 以降（今回は実装しない）**
- R2 = R1 の構造 + race-level 損失（1着の CE、top3 の補助損失、レース内のペア順序損失）。
- R2 は R1 に加えて **R2-noctx（同じ損失・文脈なし）** とも比べる。
  損失の効果と文脈の効果を混ぜないため。
- R3（Set Transformer）と R4（着順同時分布・券種確率の head）は、それぞれ前段を通過した場合のみ設計する。

## 6. 評価指標

指標は全て OOF（B2..B6 をまとめたもの）で計算する。

| 区分 | 指標 | 定義 |
|---|---|---|
| **主** | race-level win logloss | −(1/R) Σ_r log p_win(勝ち馬_r) |
| **主** | race-level win Brier | (1/R) Σ_r Σ_i (p_ri − y_ri)² |
| 副 | NDCG@3・NDCG@5 | rel = clip(6−着順,0,5)、gain 2^rel−1、log2 割引。スコア同点は馬番の小さい順 |
| 副 | ◎top3 | スコア最大の馬が3着以内に入った割合 |
| 副 | ECE | 馬ごとの p_win。等幅10 bin（`analysis/mcond/evaluate.ece`）と等件数15 bin |
| 副 | 穴帯の較正 | p_win 帯 [0,0.02) / [0.02,0.05) / [0.05,0.10) での実勝数/期待勝数（A/E）と CI。**帯は R0 の p_win で固定**（モデルごとに帯が変わる選択差を避けるため）。自モデルの p で切った版も併記する |
| 層別 | 出走頭数 | 5-8 / 9-12 / 13-15 / 16-18 |
| 層別 | 芝ダ・競馬場 | 芝 / ダ、10場 |

**統計の単位**: meeting_day。対応のあるブートストラップを B = 3,000 回、seed 20260923 で行い、
percentile で CI95 を出す（`analysis/mcond/evaluate.delta_boot` と同型）。

## 7. Gate（事前登録。全て必須）

評価は G0→G1→G2→G3→G4→G6→G7→G5 の順に行う。**どれか1つでも FAIL なら
EXP15 は FAIL で、R2 以降へ進まない**。後ろの Gate も診断用に計算して報告するが、
FAIL を覆すことはできない。

| Gate | 判定内容（Δ = 検定対象 − 比較先。負なら改善） | 合格条件 |
|---|---|---|
| **G0** | §9 の必須テスト | 最初の学習の前に全て PASS |
| **G1** | R1 対 R0 | ΔLL < 0 **かつ** ΔBrier < 0（OOF をまとめた点推定） |
| **G2** | 同上 | 開催日ブートストラップの CI95 上限 < 0（LL・Brier の両方） |
| **G3** | fold ごとの方向 | 5 fold のうち3以上で、R1 が LL・Brier の**両方**で R0 に勝つ |
| **G4** | 破綻しないこと | ① 4つの頭数帯のどれでも ΔLL の CI95 下限 ≤ 0（有意に悪化する帯が無い）。② ΔLL < 0 の帯が4つ中3以上。③ どの頭数帯でも ECE 悪化の CI95 下限が 0 を超えない。④ 芝・ダの両方で ΔLL < 0。競馬場ごとの方向一致数は報告するが Gate にはしない（1場あたり約280R） |
| **G6** | 容量の統制 | ① ΔLL(R1 − R1-noctx) の CI95 上限 < 0。② ΔLL(R1 − R1-noctx-2x) の CI95 上限 < 0 |
| **G7** | maxprob / entropy の統制 | 条件付きロジットのスタッカーで判定する（下記）。ΔLL(S_plus − S_base) の CI95 上限 < 0（B3..B6 をまとめて評価） |
| **G5** | placebo | §8 の3種すべてで、実際の文脈効果が placebo 分布の 97.5 パーセンタイルを超える |

**G7 のスタッカー**
- **S_base**: covariate は log p_i^R0 と、それに log n_r・maxprob_r・H_r を掛けた交互作用項。
  これはレースごとに温度を変える補正と同じ働きをする。
- **S_plus**: S_base に、文脈の差分 d_i = log p_i^R1 − log p_i^R1-noctx と d_i·H_r を足したもの。
- test ブロック b（b = 3..6）の予測は、それより前のブロックの OOF 予測で fit する。
- R1-noctx を基準にした版も副次的に報告する。

**FAIL の書き方（死亡台帳向け、事前に決めておく）**
- 2023 年の約2,800R では検出力に限界がある。
- そこで **FAIL は「2023 年の開催日 forward CV で検出されなかった」と記録し、
  「情報が存在しない」とは書かない**。
- R1 の結果を見る前に A/A の雑音床（§4）から最小検出効果を計算し、報告に載せる。

## 8. Placebo の設計

**構造**: 自分の馬の経路には常に本物の入力 x_i を使い、**文脈経路の入力集合だけを置き換える**。

**文脈効果の定義**: G = LL(R1-noctx) − LL(R1)。正なら改善。
placebo 版では、文脈経路に偽の集合を入れて学習・評価した R1 で同じ量を計算する。

| 記号 | 作り方 | 保存するもの | 壊すもの |
|---|---|---|---|
| **P1** 馬間 shuffle | 各レースの中で、文脈経路の各列を**列ごとに独立に**馬の間で並べ替える | 各列の場内の分布（例: 逃げ馬の頭数、平均的な能力の散らばり） | 「どの相手がどの組み合わせの特徴を持つか」という相手ごとの結合構造 |
| **P2** 文脈の交換 | 同じ区分の中で、同じ条件の別レース r′ の集合を文脈に使う。条件 = 芝ダ × 距離帯(5) × クラス群（新馬 / 未勝利 / 1勝 / 2勝 / 3勝 / OP以上）× 出走頭数が一致。相手が無ければ頭数 ±1 まで広げ、それでも無ければ placebo から除外して件数を報告 | 条件ごとに期待される文脈 | そのレース固有の出走馬構成 |
| **P3** 偽レース | 同じ区分・同じ条件・同じ期間ブロックの別レースの馬から n_r − 1 頭を非復元抽出して偽の相手集合を作る | 出走頭数・条件の分布 | 実際に一緒に走る組み合わせ |

**区分の分離**: 学習用の placebo は学習行の中から、評価用の placebo は同じ test ブロックの中から作る。
区分をまたいで混ぜると情報が漏れるため。

**主検定（readout 水準、各 placebo B = 199）**
- 各 fold で R1 の φ を凍結し、文脈を置き換えたうえで ρ だけを学習し直す。
- **本物の文脈も同じ手順で作り直す**（φ 凍結・ρ 再学習）。本物と placebo を同一手順で比べるため。
- 合格条件: G_real がどの placebo 種でも 97.5 パーセンタイルを超える。

**確認検定（全体を再学習、各 placebo B = 39、seed 1本）**
- G0-G4・G6・G7 と主検定の placebo が全て PASS した場合だけ実行する。
- φ と ρ の両方を placebo 文脈で学習し直す。
- 合格条件: G_real が39本すべてを上回る（順位 40/40、p ≤ 0.025）。

**P1 の性質（§11 R-3）**: P1 は列ごとの場内分布を残すので、たとえば
「逃げ馬が何頭いるか」だけで説明できる効果は、P1 に対しては構造的に FAIL になる。

**EXP12 の教訓**: EXP12 の O3 は、年齢×経験数の層内の交絡だけで placebo が
本物を上回った。そのため P2・P3 の抽出は条件の層の中で行う。

## 9. 必須テスト（G0。最初の学習の前に全て PASS させる）

| # | テスト | 具体的な判定 |
|---|---|---|
| T1 | 入力順の並べ替え | eval モード（dropout off）で、レース内の馬の順を無作為に並べ替えると、出力が同じ置換で並び替わるだけ（誤差 1e-5 以内）。レース単位の量（Σp、文脈ベクトル）は不変 |
| T2 | レース間の情報混入 | 同じバッチのレース B の入力を変えても、レース A の出力が**完全に**同じ。BatchNorm など、バッチの統計を使う層が無いことを静的にも検査する |
| T3 | padding の無影響 | padding 行に乱数のゴミを入れても実馬の出力は同一。padding は softmax で −inf、勾配は 0 |
| T4 | 取消後の再正規化 | 馬 h を除くと、**文脈を h 抜きで計算し直した**出力と一致する（古い確率を割り直すだけでは不可）。残りの Σp_win = 1 |
| T5 | 出走頭数 5〜18 | n = 5..18 の全てで動き、Σp_win = 1、n ≥ 3 なら Σp_top3 = 3。n > 18 は黙って切り捨てず assert で落とす（旧 RaceTransformer は18頭で黙って打ち切っていた） |
| T6 | 確率の和 | 全 OOF レースで \|Σp_win − 1\| < 1e-6 |
| T7 | 未来削除の不変性 | 日付 T 以降の行を消して特徴・前処理・文脈を作り直しても、T 以前の行のモデル入力が1バイトも変わらない（EXP01 と同型） |
| T8 | 前処理が fold 内だけで fit されていること | 全ての fit 対象（scaler・語彙・頻度・hash・LabelEncoder・τ）の fit 行が各 fold の学習行の部分集合であることを assert。test ブロックの行 ID が混じったら落ちる |
| T9 | 馬 ID を記憶させない | 特徴一覧に血統登録番号・馬名・`前走レースID(新)` 系が無い（§11 R-4 の結論に従う）。カーディナリティが学習行数の 1% を超える列は、明示的な許可リストに無ければ落ちる |
| T10 | レース ID を特徴にしない | 今走の `レースID(新/馬番無)`・rid16・meeting_day が入力に無い。`Ｒ`・`開催`・`前走日付` は許可リストに明記する |
| T11 | 当日・結果由来の列を入れない | 今走の単勝オッズ・人気・馬体重・着順・走破タイム・通過順などが入力に無い（禁止リスト） |
| T12 | 2024 年以降が存在しない | ローダーの出力で `date.max() <= 20231231`、読み込み行の hash をログに残す |
| T13 | 集合の一致 | 学習時と評価時で同じ規則（同じ rid16 の行＝集合）が使われていること。DNF 感度分析版では DNF 馬が文脈に入り、ラベルは着外になっていること |
| T14 | カテゴリ表記の一致 | `category_normalize.py` を通した後の語彙で、serve 形式の表記（例「ダート」）が学習語彙の値（「ダ」）に対応すること |
| T15 | 再現性 | seed を固定して同じ fold を2回学習すると、同じ OOF 予測になる（決定的アルゴリズムを設定する。許容誤差は事前に記録） |
| T16 | 文脈経路の遮断 | R1-noctx で、他馬の入力を任意に変えても自馬の出力が変わらない（双子の対照が本当に文脈を見ていないことの証明） |

## 10. カテゴリ表現の扱い（レース文脈の効果と混ぜない）

| 記号 | 表現 | 使う場所 |
|---|---|---|
| C0 | LabelEncoder の整数を数値として使う（v6 と同じ。NN では標準化） | R0、比較用の R1-noctx-C0 |
| C1 | 頻度符号化 + hash（高カーディナリティ列は64バケツ） | 比較用の R1-noctx-C1 |
| C2 | 学習埋め込み（§5） | **R1 系の主案（事前固定）** |
| C3 | CatBoost（native カテゴリ）の馬ごと行モデル | 比較用の R0-cat |

**分離の規則**
- **文脈の効果は C を固定したまま**測る（R1 と R1-noctx はどちらも C2）。
- カテゴリの効果は**文脈なしのモデル同士**で測る（R1-noctx-C0 / C1 / C2、R0 と R0-cat）。
  これは **Gate 外の副次報告**とする。
- C を test ブロックの結果で選び直すことは禁止。
- R0-cat の損失は、使える CatBoost のバージョンに `LambdaMart` があればそれを使う。
  無ければ YetiRank を使い、損失の交絡があることを明記する
  （既存の −1.81pt はこの交絡を含む。監査 §3.F）。

## 11. レビュー論点（実装前に決めていただきたいこと）

**R-1. Gate 1 は3つの差を混ぜている**
- R1 対 R0 の差には、次の3つが同時に入る。
  - (a) 表形式データでの NN と GBDT の差
  - (b) pointwise 損失と LambdaRank の差
  - (c) レース文脈の効果
- 過去の証拠
  - PRED-01（pointwise の binary）は LambdaRank に ◎top3 で −1.74pt 負けた。
  - 旧 RaceTransformer は交絡付きで −7.67pt 負けた。
- したがって (c) が実在しても、(a)・(b) のために G1 で落ちる可能性が高い。
- 【既定案】ご指定どおり G1 = R1 対 R0。
- **推奨する代替案**: G1 を2つに分ける。
  - G1a（R1 対 R1-noctx）+ G5・G6・G7 で「文脈情報が実在するか」を判定し、R2 へ進むかを決める。
  - G1b（R1 または R2 対 R0）で「置き換える価値があるか」を判定し、R3・R4・馬券接続へ進むかを決める。
  - 理由: R2 で race-level 損失を入れると (b) は縮む可能性がある。今の規則では、R2 を試す前に打ち切られる。

**R-2. R1 の損失**
- 【既定案】段階ラベルに対する pointwise MSE。
- 代替案
  - BCE（1着）: 情報量が少ない。
  - レース内 softmax CE: R2 の一部を先取りすることになり、R1 と R2 の区別が崩れる。
- R-1 で代替案を採るなら、既定案のままでよい。

**R-3. P1 は列ごとの場内分布を残す**
- 逃げ馬の頭数のような「数」で説明できる効果は、P1 に対して構造的に FAIL になる。
- 【既定案】ご指定どおり P1 も合否条件に含める（相手ごとの結合構造まで要求する、厳しい設定）。
- 代替案: P1 は分解用の報告にとどめ、合否は P2・P3 で判定する。

**R-4. v6 の入力のうち要判断の列（監査 §6）**
- 対象
  - `馬主(最新/仮想)`: 最新値で上書きされており、as-of に違反する。
  - `前走レースID` 2列: 集合モデルでは「前走で同じレースを走った」という ID ベースのリンクになる。
- 【既定案】R0 と R1 の両方から外す（117特徴）。本番互換の R0-ref は参考値として並べる。
- `母馬` は Stage 1 の監査で扱いを確認してから決める。

**R-5. 市場を条件にした補助検定を入れるか**
- 2023 年でも historical_pre_snapshot（TANPUK、発走26-30分前）は構築できる
  （`project_market_provenance_audit_20260922` で EXP13 Gate0A の「0%」は訂正済み）。
- EXP02-12 の能力系の表現は、最終的に「v6 + 市場」を基準にして判定されてきた。
- 【既定案】Gate 外の報告として G7 の S_base に市場の logit を足した版を出す。
- 代替案: R2 へ進む条件に加える。

**R-6. DNF を含む文脈**
- 【既定案】主解析は master_v2 のまま、DNF を含む版は Gate 外の感度分析。

**R-7. placebo の計算量**
- 【既定案】readout 水準で各 B = 199、全体再学習の確認検定で各 B = 39。
- 確認検定は、約 39 × 3 × 5 = 585 回の NN 学習になる。
- Stage 1 で1 fold の学習時間を測ってから、確認検定を P2・P3 に絞るかどうかを決めたい。
  ただし絞るかどうかは**結果を見る前に**決める。

**R-8. 検出力**
- 評価対象は約2,800R しかない。
- R1 を見る前に A/A から最小検出効果を出す。
- それが過去の文脈効果の規模（ΔAUC 1e-3 前後）より大きい場合は、本実験では小さい
  効果を検出できない。その場合でも FAIL の扱いは変えず、記録の文言を
  「未検出」とする（§7）。この扱いで良いかを確認したい。
