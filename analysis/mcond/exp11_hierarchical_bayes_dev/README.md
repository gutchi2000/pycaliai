# EXP11 — 階層ベイズによる疎データ・未知条件への外挿

## 目的

全体精度ではなく、**事前固定した疎データ領域**（career starts 0-2/3-5、
初距離、初コース、昇級初戦、転厩後初戦、低頻度騎手×調教師ペア、低サンプル
種牡馬条件）に限定して、階層ベイズ/部分プーリングが現在のunknown処理・
頻度統計・LightGBMより安定した確率を出せるかを検証する。

**主仮説**: 全体精度では差がなくても、疎データ領域に限れば、階層縮約が
現在のunknown処理・頻度統計・LightGBMより安定した確率を出せる。

## 絶対条件

EXP01-10・v6・compute_bets.pyは変更しない。新規作業は
`analysis/mcond/exp11_hierarchical_bayes_dev/`へ限定する。
Gateは全体平均ではなく対象の疎データ領域限定で実施する。

## Stage 0 の要点

- **先行研究**: 「経験ベイズ収縮」という技法自体は3回実装・検定・死亡済み
  （EVT分散σ・baba馬場適性・EXP01陣営選択のK_TRAINER/K_JOCKEY/K_HORSE、
  いずれも全体populationでの特徴追加として死亡）。しかし「疎データ領域
  限定・確率の安定性」を目的とした階層ベイズは**真に未着手**。
- **エンコード方式**: 種牡馬・母父馬・馬主・生産者・騎手・調教師は全て
  単純LabelEncoder（順序符号）、ローリング統計は騎手・調教師・馬自身・
  馬×コース・馬×騎手ペアのみ、種牡馬/母父/馬主/生産者にはローリング統計
  なし。**馬の識別子自体はLEAK_COLSとして特徴から除外**されている。
- **未知カテゴリ処理**: 学習・配信とも単一の`"__NaN__"`バケットへ一括縮約、
  部分プーリングは一切なし。LightGBMには`categorical_feature`が一度も
  渡されておらず、ネイティブカテゴリ分割すら使っていない。
- **疎データ領域の実測（2023年developmentのみ）**: 8領域全てで十分な
  サンプルサイズ(最小419件)。v6-市場相関は全領域で高い(0.82-0.88)。
  **低頻度騎手×調教師ペアで62%の系統的過大予測を発見**(v6予測0.059 vs
  実現0.036)——他の全領域は予測とほぼ一致しており、この領域だけが
  明確な異常。Stage1以降の最有力候補。

詳細は`PRIOR_ART_AUDIT.md`/`DATA_AUDIT.md`参照。
